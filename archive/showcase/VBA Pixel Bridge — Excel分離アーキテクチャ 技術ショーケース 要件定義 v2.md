# VBA Pixel Bridge — Excel分離アーキテクチャ 技術ショーケース 要件定義 v2

reader-data-viewer の本番アーキテクチャを流用した検証／デモ用ショーケース。
「Excel VBA だけでどこまでできるか」の技術ショーケースを兼ねる。
v1 からの変更点は各項の末尾に `※v1 からの変更` として記す。

---

## 1. 目的

- 検証／デモ用ショーケース
- 技術ショーケース（VBA のみでの外部アプリ連携・非同期化・GUI 描画）

## 2. 制約

- VBA のみ。C# の埋め込みと、Excel 以外の外部 helper は使わない。重い処理は
  COM で起動した別プロセスの Excel（BE）へ渡す
- Win32 API なし、Shell なし
- 成果物は VBA のソース一式（標準モジュール 4 枚 ＋ クラスモジュール 8 枚）。
  当初の「.bas 1 枚」から、責務ごとに分ける方針へ変更した。
  状態と副作用はクラスへ閉じ込め、標準モジュールは公開の入口と、状態を持たない
  計算だけを残す。分ける単位は「寿命と資源の境界が同じもの」で、外の窓を扱う
  一式（UIA・メモ帳・窓の一覧）と、ベンチ 1 回ぶん（やりとりの JSON・表示用
  ブック・計測）はそれぞれ 1 つの部品にまとめる。外部ライブラリ・アドインは
  足さない（部品の一覧と行数は README）
- 既定の参照設定以外に追加するのは UIAutomationClient のみ
- ユーザーのディレクトリを汚さない（一時ファイルは Temp、Excel 終了時に削除）

## 3. アーキテクチャ

- FE：疑似ピクセル GUI の Excel（ユーザーが操作する側）
- BE：別プロセスの非表示 Excel（重い処理を担当）
- FE⇔BE 通信：Temp フォルダの JSON と、計算した桁を置く `pi.txt`。
  Excel 終了時に削除

### 3.1 BE の起動と実行（実装上の要点）

- BE の起動は `CreateObject("Excel.Application")` で可。COM のみで Win32 API も Shell も不要。`.Visible = False` で非表示
- **FE→BE の呼び出しは即 return 必須**。`beApp.Run "BeMain"` を同期で呼ぶと処理完了まで FE がブロックされ、非同期化の意味がなくなる。BE 側の入口で `Application.OnTime` を仕込んで即座に戻し、実処理は BE 自身のタイマーで回す
- **BE 用ブックの置き場所**：`%TEMP%\pixelbridge\` へ軽いコピーを作り、読み取り専用で開く。配布物のフォルダには何も書かない（配るのは 1px / 2px / 4px の FE ブック 1 冊ずつだけ）。プログラムから開くときのマクロは `AutomationSecurity = Low` で通す。これは置き場所の信頼設定とは別の口で、`%TEMP%` でも有効になる。コピーは正常終了時に消し、異常終了で残っていても次回起動時に消してから作り直す
- `Auto_Open` は `Workbooks.Open` では走らないため、FE が
  `Application.Run "'<book>'!PbBeBootstrap"` で BE 専用入口を名前で直接呼ぶ。
  入口は `Application.OnTime` を仕込んですぐ戻り、FE は直後に BE への COM 参照を捨てる

※v1 からの変更：BE 起動可否とマクロ信頼の制約を明記

## 4. 画面構成

- **812 × 812 の正方形。スクロールなしで収まる**
- 想定：1920×1080 の左半分へ Excel の外枠を合わせ、右半分にメモ帳を並べて使う。
  盤面は Excel の可視範囲に収まる寸法
- 構成：ヘッダー帯 ＋ **大きく 2 分割** ＋ フッター
  - 上：**UI Automation 連携**（メモ帳との双方向同期 ＋ ウィンドウ制御 ＋ 要素情報）
  - 下：**フロントエンド・バックエンド分離**
- グリッド線・見出し・横スクロールバー・シートタブを隠す。リボン・数式バー・
  ステータスバーは残し、終了時に表示設定を戻す
- 疑似ピクセル描画の粒度は **ビルド時に 1px / 2px / 4px から利用者が選ぶ**。設計座標は 812×812 px のまま。変わるのは「1 セルが何デザイン px を受け持つか」だけ。
  - セルの実寸は「1 デザイン px = 0.75pt」をねらいとし、**その寸法で盤面が画面に入らない端末では、入る最大の整数デバイスピクセルへ切り下げる**（起動時に実測。1920×1080 / 125% では 3 種とも 1 デザイン px = 1 デバイス px になる。0.75pt 固定だと実行ボタンとフッタが最初から画面外だった）
  - 既定値は置かない。選ばずにビルドはできない
  - 選んだ値は成果物のファイル名（`VBA Pixel Bridge 2px.xlsm` 等）と画面フッタ（`1 セル = 2px`）の両方に出す
  - Excel のグリッド線は粒度にかかわらず隠す。選んだ粒度は成果物名とフッターで示す
  - **角丸は角にかかるセルの被覆率で下地と混色する**（v2 内の変更 2026-08-20）。セル 1 つは 1 色しか持てないので、塗る / 塗らないの 2 択では 1px が階段、2px が潰れ、4px は角丸そのものを諦めることになる。混色なら 3 種とも角が丸く見える（1px は 1 セル = 1 デバイス px なので本物のピクセルアンチエイリアスになる）

※v1 からの変更：2×2 のカードグリッド → 上下 2 分割。シート上の補助 UI は非表示
※v2 内の変更：1 セル 1px 固定 → 1 / 2 / 4px の選択制。セル実寸に「画面に収まる」制約を追加（これで 1px も 1 秒アニメのまま通常利用できる。README の実測を参照）

### ヘッダー帯

- アプリ名
- 起動からの経過時間
- 同期ステータスのランプ ＋ ポーリング回数
- ライトテーマ 1 種
- アニメーション（時計・ドット・進捗の更新）は**常時 1 秒**。速さの切替は置かない

### 上段：UI Automation 連携

**メモ帳 ⇄ Excel 同期パネル（左）**

- ある程度の大きさのテキストボックスで**フリー同期**。文字種別判定・1 文字制限・送信ボタンは廃止
- **つなぐメモ帳は 1 枚だけ。テキストボックスも 1 つ**（2026-08-19 変更。それ以前は 2 窓 2 ボックス）
- 対象メモ帳の文書要素がフォーカス中なら、テキストボックスの枠を強調
- 同期の開始／停止トグル
- 状態表示：`SetValue 待ち` / 取得時刻

※v1 からの変更：判定カテゴリ表示（「これは数字です」）を全面廃止。読み取りと書き込みを分離せず同期に統合

**ミニマップカード（右）**

- 実画面を縮小し、この Excel と、つないだメモ帳 1 枚だけを追う。デスクトップ全体の
  列挙は行わず、通常時の探し直しは 4 ティックに 1 回
- ツールバーのボタンは **最大化**（メモ帳を画面右半分へ合わせる）と **最小化**。
  ミニマップの複数セルを選ぶと、その範囲へメモ帳を移動・リサイズする
- 1 セル選択はクリック位置を画面座標へ逆算し、保持している窓矩形のヒットテストで
  ウィンドウ名・クラス・pid・矩形・移動可否を 2 行に表示する
- 1 セル選択では窓を動かさない。複数セルの選択だけが移動操作

※v1 からの変更：左右 / 上下の整列ボタンを、最大化 / 最小化と範囲選択へ変更

**要素情報（ミニマップ上部と同期カード）**

- 点の情報はミニマップ上部の 2 行へまとめる。実装は `ElementFromPoint` を直接呼ばず、
  ミニマップに保持した 2 窓の矩形をヒットテストする
- フォーカスは、既に掴んでいるメモ帳の文書要素の `HasKeyboardFocus` を読み、pid と
  本文長だけを同期カードに表示する。`GetFocusedElement` は使わない
- 自分の Excel の UIA 要素を常時作らない。セル書き込みへ同期コストを載せないため

### 下段：フロントエンド・バックエンド分離

- FE / BE / 表示用 Excel の状態ボックス。状態札は `待機` / `動作中` に揃え、
  失敗時だけ `失敗` を出す。詳しい段階はジョブ行と記録に出す
- **進捗の可視化は「30 秒の計器」**（v2 内の変更 2026-08-20。それ以前は 10×10 のマトリクス → 円周率の桁の値を色にした 67×12 のランプ盤）。図は 3 つで、色は 2 つだけ ── **緑 = FE の時間、青 = BE の成果**
  - **帯（30 列）**：1 列が 1 秒。床（緑）はその秒に FE がティックした証拠、その上に積む山（青）はその秒に表示用 Excel まで届いた桁。1 桁も届かなかった秒でも床は立つので緑は途切れない。列と列のあいだに隙間は置かない（離すと稜線ではなく粒の集まりに見える）
  - **走査点**：いま塗っている列の真上に出て、1 秒ごとに右へ 1 列動く
  - **下線**：経過 / 30 秒。待機は空、実行で伸び、完了で満ちる
  - 意味のない波形アニメーションは廃止。**動いていない図も置かない**（ランプ盤は先頭 804 桁で埋まりきり、開始 2〜3 秒で静止していた）
- 中央に `%TEMP%\pixelbridge\` のレーン
  - `command.json →`（FE→BE）
  - `← progress.json`（BE→FE）
  - 実際に送受信したティックだけレーンを点灯する。payload 自体は盤面へ出さない
- 実行ボタンは `円周率計算` の 1 つ。経過秒・計算桁・表示桁をジョブ行に出す
- 完了ダイアログは出さず、結果を盤面に残す

※v1 からの変更：FE/BE の稼働状況とファイルのやりとりを可視化。BE のダミー波形は削除

### フッター

- キーボードショートカット一覧
- 1 セルのサイズ / 角丸のセル数 / 30 秒計器の列数と高さ
- **トースト通知は廃止**（状態の変化そのもので示す）

※v1 からの変更：右下からのトーストを削除

### 共通

- 各ボタンにホバーツールチップ（ハイパーリンクの ScreenTip）
- API 名はカード見出しや説明へ組み込み、独立した技術ラベルは増やさない

## 5. 同期仕様

- UI Automation でメモ帳をポーリング。**間隔 1 秒**
- 取得した本文はそのままテキストボックスへ反映。文字種別の判定はしない
- テキストボックス側が編集されていれば `ValuePattern.SetValue` で書き戻し、差分がなければ `GetValue` のみ
- **対象は 1 枚だけ**。2 枚目以降は掴まない
- **掴む窓はウィンドウハンドルで固定する**。Z 順（列挙順）が変わっても持ち替えない。並び順で選ぶと、利用者が窓をクリックしただけで別の窓へ古い本文を書き戻し、文章を消す
- 最小化されても掴んだ要素は手放さない（手放すと最大化でも範囲選択でも戻せなくなる）
- **結び直した直後の 1 回は必ずメモ帳 → アプリの向きで揃える**。アプリが利用者のメモ帳の文章を消したり失ったりしてはならない
- メモ帳は**起動している前提**。アプリ側から起動はしない

※v1 からの変更：判定仕様を削除し、1 文字制限を撤廃。0.5 秒案は実測後に 1 秒へ戻した
※v2 内の変更：スロット固定と「メモ帳側が正」の規則を明文化（実害の再発防止）

## 6. 重い処理 ── 円周率ベンチ（30 秒）

※2026-08-19 に差し替え。それ以前は「メモ帳 2 枚を使う原稿 → 清書」で、
FE 実行 / BE 実行の二択だった。二択・処理種類の選択・旧 100×100 セル負荷デモは廃止。
※2026-08-20 に 15 秒 → **30 秒**。同時に進捗の可視化を「30 秒の計器」へ
入れ替え（§ 下段を参照）、表示用 Excel は書いた先を自分で追うようにした。

- 明示ボタン **1 つ**（表示名「円周率計算」）で実行。常時は走らせない
- 登場人物は 4 つ
  - **FE Excel**：この疑似ピクセルアプリ。1 秒ポンプで全部を回す
  - **BE Excel**：別プロセス・非表示。30 秒だけ円周率を実際に計算する
  - **表示用 Excel**：BE とは別の一時ブック。計算できた桁が増えていく様子をセルへ出す。**ディスクへは保存しない**
  - **メモ帳**：つないでいる 1 枚
- FE / BE のやりとりは従来どおり Temp の JSON（`command.json` / `progress.json`）。桁そのものは `pi.txt`
- **既知の円周率文字列を流してはいけない。** BE で実際に計算し、計算された桁を表示用 Excel へ順次反映する
  - 使うのは Rabinowitz-Wagon の spigot（有限桁版）。桁を頭から 1 つずつ吐く。配列長 `ln = 10n/3 + 1` が「何桁まで正しく出せるか」を決めるので、途中で打ち切っても出した桁は正しい
  - `n` は走る前に 0.15 秒だけ内側ループを空回しして端末の速さを測り、30 秒で届く値を選ぶ（固定値は端末次第で桁が変わる。実測）
  - BE は 30ms に 1 回 `DoEvents` する。入れないと FE の UIA 列挙が BE を待って返らず、逃がした意味が無くなる（実測）。毎桁だと `DoEvents` 自体が重すぎる（1 回 1.6ms）
- 配置と準備が完了してから 30 秒を計測する。開始時の配置は
  - FE Excel：画面左半分全面（起動時に置いたまま。ベンチでも動かさない）
  - 表示用 Excel：右上 4 分の 1
  - メモ帳：右下 4 分の 1
  - 三つを前面に出して開始する。表示用 Excel はベンチ表示専用で、メモ帳用の操作対象には混ぜない
- FE には**経過時間・計算済み桁数・表示済み桁数**を出し、終了後も最終結果を残す
- **正式な結果は、30 秒以内に正しく計算され、表示用 Excel まで実際に反映された桁数**。内部だけの計算桁数はスコアにしない。30 秒を越えたティックでは表示を足さない（終わりを見張るのは 1 秒ポンプなので、最後に数えられるのは 29 秒台のティック）
- **表示用 Excel は書いた先を自分で追う。** いちばん新しい行が下端へ来るまで送り、見出しの 3 行は凍らせて残す。送らないと、行は 1 秒に 2〜3 行ずつ増えているのに窓は最初の数行を映したままで、何も起きていないようにしか見えない
- 完了ダイアログは**出さない**。結果は盤面に残る。モーダルは利用者の次のクリックを飲み込む（実機で「ベンチ直後の最大化が効かない」として出た）
- ベンチ中も、メモ帳の最大化・最小化、ミニマップ範囲選択による移動・リサイズ、双方向同期、1 秒アニメが実際に使えること
- 終了（30 秒で自動）
  - 表示用 Excel を保存せずに閉じる
  - 非表示 BE を終了する
  - 一時 JSON 等を削除する（フォルダごと）
  - FE 以外の追加 Excel プロセスを残さない
  - メモ帳の内容を消さず、別ウィンドウへの誤書戻しも起こさない
  - エラーや途中終了でも同じ後始末が働くこと。**閉じる要求のときは `BeforeClose` で済ませる**（`Auto_Close` は走らないことがある。実測）

## 7. ウィンドウ操作

- UIA `TransformPattern.Move / Resize`、`WindowPattern.SetWindowVisualState`
- **監視・同期・操作対象のメモ帳は 1 枚だけ**。疑似ピクセル GUI 上の同期用テキストボックスも 1 つ。2 枚目用の UI・状態・配列・選択・切替・二重同期は持たない
  - いったん掴んだ窓は離さない。`FindAll` の並びは Z 順で、利用者のクリック 1 つで入れ替わる。並び順で選ぶと入れ替わった先へ前の窓の本文を書き戻して文章を消す（実害として報告済み）
- ボタンは 2 つ
  - **最大化**：対象メモ帳を画面の右半分いっぱいへ移動・リサイズする。OS の全画面最大化ではなく、FE Excel を左半分に固定したまま右半分へフィットさせる
  - **最小化**：対象メモ帳をタスクバーへ格納する。掴んだ要素は手放さないので、そのあと最大化でも範囲選択でも戻せる
- ミニマップ上のセル範囲選択による、任意位置への移動・リサイズは継続する
- **Excel は起動直後に一度だけ画面の左半分へ合わせ、以後は位置も大きさも変えない**。メモ帳の最大化・最小化・範囲リサイズで FE Excel の矩形を変えない
- 画面サイズは UIA ルート要素の矩形から取得
- 最大化されたウィンドウは `CanMove` が False になるため、先に通常表示へ戻す
- Excel 自身の初期配置は Application の座標（ポイント×実測 px/pt 比）で行い、単位系を UIA の画面ピクセルに揃える（DPI 問題の回避）。**自分の窓の UIA 要素は作らない**（作るとセル書き込みが毎回 130ms 級になる。実測）
- ミニマップの 1 セル選択は、クリック位置を画面座標へ逆算し、保持している窓矩形を
  ヒットテストして、その点にある窓の情報を出す。動かす相手を選ぶ操作ではない ──
  相手は常につないだメモ帳 1 枚
- **注意（2026-08-19 訂正）**：v2 の旧版には「メモ帳 11.2606 は TransformPattern をどの要素にも公開しない、Win32 なしでは回避策が無い」と書いてあったが、**これは誤り**。原因は製品側の定数取り違えで、`UIA_TransformPatternId` を 10003（= RangeValuePattern）にしていた。正しい 10016 を渡せば、同じ端末・同じメモ帳でネイティブ COM UIA から `CanMove=True / CanResize=True` が取れ、`Move` / `Resize` が通る（実測）

## 8. ショーケース要素（全 10）

1. UI Automation による外部アプリ連携
2. メモ帳 1 枚との双方向フリー同期（読み取りと書き込みの統合）
3. 1 / 2 / 4px を選べる疑似ピクセルのフロントエンド描画
4. FE/BE 分離による固まらないアーキテクチャ
5. FE / BE / 表示用 Excel の状態とファイル通信の可視化
6. この Excel と対象メモ帳のミニマップ
7. メモ帳の最大化・最小化・範囲リサイズ（Win32 なし）
8. 矩形ヒットテスト / `HasKeyboardFocus` / クリック座標の逆算
9. ホバーツールチップ（ハイパーリンクの ScreenTip）
10. キーボードショートカット（Application.OnKey）＋ 1 秒アニメ

※v1 からの変更：文字種別判定・疑似ピクセルアニメ（トースト/スピナー）を外し、同期と FE/BE 可視化を主役に

## 9. 技術上の制約と回避策

| やりたいこと | 素の可否 | 採る方法 |
|---|---|---|
| マウスカーソル座標の取得 | 不可（Win32 GetCursorPos が必要） | ミニマップのクリック位置から逆算 |
| ドラッグでウィンドウを動かす | 連続追従は不可（マウスイベントが取れない） | ミニマップのセル範囲を選び、選択確定時に 1 回だけ Move / Resize |
| メモ帳の起動 | Shell / WScript.Shell は制約違反。WMI `Win32_Process.Create` なら COM のみで可、`FollowHyperlink` は警告ダイアログが挟まる | 行わない。**起動済みを前提**にする |
| 非表示 Excel（BE）の起動 | 可（`CreateObject("Excel.Application")`、COM のみ） | 採用。呼び出しは即 return、BE コピーは Temp に置き `AutomationSecurity = Low` で開く |
| Windows のトースト通知 | 不可（Win32 / WinRT が必要） | 採用しない（シート内トーストも廃止） |
| HTML ダッシュボードをブラウザ表示 | 可（Temp + FollowHyperlink） | 採用しない（疑似ピクセル GUI が霞むため） |
| data: URI でブラウザ表示 | 不可（主要ブラウザがブロック） | — |
| 0.5 秒ポーリング | `Application.OnTime` は秒未満が不安定、Sleep は禁止 | 実測に基づき 1 秒を採用（下記 10 参照） |

## 10. 実装時に判断した事項

- **ポーリングは 1 秒**。`Application.OnTime` の秒未満指定は即時発火または秒単位へ丸まった
- 重い処理は、端末速度を 0.15 秒測って桁数を決める 30 秒の円周率計算
- セル実寸は起動時に測り、画面へ収まる最大の整数デバイス px を選ぶ。ビルド時の
  `PB_UNIT` は必須引数または対話メニューで 1 / 2 / 4 を選ぶ
- BE コピーは Temp に置き、`AutomationSecurity = Low` で読み取り専用に開く
- UIAutomationClient は早期バインディングする。`ElementFromPoint` の tagPOINT は使わず、
  保持している矩形のヒットテストで代替する
- デジタル庁デザインシステム系の色・書体・余白をライトテーマへ適用する

## 11. デザイン

- デジタル庁デザインシステム（DADS β v2 系）の色・書体・余白を採用
- キーカラー Blue-900 `#0017C1`
- ニュートラルは Solid Gray（境界 `#CCCCCC`、副文字 `#767676`、文字 `#1A1A1A`）
- 書体：和文は Noto Sans JP（無ければ Yu Gothic UI）、数値・API 名は
  Noto Sans Mono（無ければ Consolas）
- カードは角丸 8px、塗りボタンは角丸 6px、枠ボタンは直角。余白は 4px グリッド
- ライトテーマ 1 種。ダーク切替は持たない
