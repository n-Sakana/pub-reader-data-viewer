# UI 正本仕様 (`Reader Data Viewer_ver3.html` から抽出)

先生の見本 **`Reader Data Viewer_ver3.html`** が UI/UX の正本。この文書は、その見本を
**実際にブラウザで描画して計測した値**をまとめたもので、C# 版と Excel VBA 版の実装契約になる。
見本そのものは読むだけで、変更・整形・移動はしない (ver1 / ver2 も残す)。

- 計測: Chromium、viewport **1280×860 CSS px**、devicePixelRatio 1。カード実測 **1240 × 689 px**。
  先生のスクリーンショットは 1871 px 幅 = 同じ 1240 px 幅を **150% 表示**したもので、実機の
  Windows 表示スケール 150% に一致する。実装は論理 px で組み、DPI スケールに追従させる。
- 参照画像: `work\ui-ref\ref-01..09-*.png` (状態ごと、すべて ver3 から取得)
- 版の履歴 (見本側の変更):
  - ver1 → ver2: サマリー行の折り返しを廃止 (1 行固定)、gap 一律化、副題を nowrap。
  - ver2 → ver3: カードの最小幅 960 → **1240 px**、サマリーの gap/padding を 20.4 → **13.6**、
    入力欄 128 → **110 px**、担当者ブロックを stretch + nowrap、**副題と統合レコード左列を
    選択状態に連動**(未選択は「—」)、最終更新を `MM-DD HH:mm` の短縮表記に。
  - **ver4: 設定モーダルとピッカーの正本**。メイン画面は ver3 のまま。モーダルは
    **1060 × 764**、ピッカーは **460 × 292.8**。計測値は
    `docs/ui-ref-settings-geom.json` / `src/app/csharp/Rdv3SetGeom.cs`、設計は 12–13 章。

## 6. 実装 (C# 版)

### 6.1 座標は見本の実測値そのもの
`src/app/csharp/Rdv3Geom.cs` が見本の矩形表 (カード相対・CSS px)。`Rdv3Form.Layout1()` は
この表を device 矩形へ写して辞書 `rc` に入れ、**描画・実コントロールの配置・受け入れ検査の
ダンプはすべて同じ辞書を読む**。自前のフレックス計算はしない。

- 幅が増えたとき動く要素は 3 種類だけ: 左固定 / 右寄せ (再検出ボタン・入力群・担当者・タグ) /
  伸縮 (パネル・罫・表・レコード右カラム)。
- 高さが増えたぶんは候補一覧と統合レコードで折半 (見本の 6 グリッド行はすべて `auto` なので
  伸びる行が無い。伸ばし先は「行がもっと見える」候補一覧と長文ボックスが妥当)。
- **文字が見本のサンプルより長い場合だけ**要素は見本より広くなり、後続がその差だけずれる。
  重なりは構造的に起きない。入り切らない場合は省略記号で止める。

### 6.2 ウィンドウ最小幅は内容に追従する
見本の `min-width: 1240px` は下限であって約束ではない。代替フォントや長いユーザー名では
同じ 1 行がそれ以上を要求するので、`EnsureRoom()` が**必要幅を測って最小幅を上げ、
ウィンドウを一度だけ広げる** (作業領域が上限)。縮小方向は設計サイズより下げない。

### 6.3 フォント代替 (同梱しない・Windows 標準搭載のみ)
フォントファイルは**再配布もインストールもしない**。使うのは Windows に最初から入っている
書体だけで、無い環境では順に下へ落ちる。

| 用途 | 見本 | 採用 (先頭から順に探す) | 実測 |
|---|---|---|---|
| 本文・ラベル・表 | Barlow 400/700 | **Meiryo UI** → Yu Gothic UI → MS UI Gothic → Segoe UI | Yu Gothic UI は 10〜13px で細く読みにくい。標準搭載で最も濃いのが Meiryo UI (比較 `work/font-compare*.png`) |
| 見出し・ブランド | Barlow Condensed 600 | Bahnschrift SemiBold Condensed | "Reader Data Viewer" 19px: 見本 132.1 → 実装 +0.4px |
| 3 つの大数値 | Barlow Condensed 600 | Bahnschrift SemiBold | "00016168" 34px: 見本 131.2 → 実装 133 |
| 太字 (値・表見出し) | 700 | 本文書体の Bold | Meiryo UI に Semibold の版は無い |

**Noto Sans JP は使わない**。見た目は良いが Windows 標準ではなく、同梱もしない方針なので
入っていない端末で崩れる。

字間 (`letter-spacing`) は GDI/GDI+ に設定が無いので、対象の文字列だけ 1 グリフずつ
サブピクセル位置で描く (`DrawTracked`)。適用するのは **10px のセクションラベルだけ** (見本の
0.1em)。大数値とブランドには**適用しない**:

- 見本の Barlow Condensed は細いので 0.06em の空きが効くが、代わりの Bahnschrift は元々
  広く、同じ字間だと**間延びして見える**
- 番号は将来**数字と英字が混在**する。1 グリフずつ置くと混在時に間隔が不揃いに見えやすい

### 6.4 計測は GDI+ に統一
`TextRenderer.MeasureText` は `NoPadding` を付けても**約 0.57em の下駄**を返す
(実測: 13px の漢字 1 文字 = 21、11 文字 = 151、送り幅自体は正しく 13)。
この数値で箱を作ると全要素が半 em ずつ太り、サマリー行が自分の逃げ道規則に引っかかって
自分自身を省略した。**計測も描画も GDI+ (typographic) に統一**し、結果はキャッシュする。

### 6.5 状態別スタイル (見本の CSS どおり)
| 対象 | 通常 | ホバー | 押下 | 無効 | フォーカス |
|---|---|---|---|---|---|
| 主ボタン | accent | accent-600 | accent-700 | 透過 45% | 2px accent 枠・2px 外側 |
| 副ボタン | 枠 divider | ink 7% | ink 14% | 透過 45% | 同上 |
| 入力欄 | 枠 divider | 枠 ink 45% | — | — | 枠 accent + 2px 枠 (offset 0) |
| 候補行 | — | ink 4% | — | — | — |
| 選択行 | accent-100 + 左 2px accent 帯 | | | | |
| 状態タグ | DONE=accent / HOLD=枠線 / VOID=不透明度 50% | | | | |

フォーカス枠は見本の `:focus-visible` と同じく**キーボード操作のときだけ**出す
(Tab/矢印で立ち、マウス押下で消える)。

## 7. 受け入れ検査

「見た目のコピー」ではなく**壊れないこと**を条件にした。判定は 2 本立てで、両方通過が合格。

1. **忠実度** — 設計サイズ (1240×689, 100%) で、名前付き 67 要素の矩形を見本の実測表
   (`docs/ui-ref-geom.json`) と数値比較。レイアウトが決める成分 (すべての y/h、
   および構造要素の x/w) は **±2px 以内**。
2. **健全性** — サイズ 4 種 × 拡大率 3 種 × 状態 14 種 × データ 2 種 = **336 通り**で

## 14. VBA 版の画面 (同じ矩形表から、セルを疑似ピクセルにして組む)

C# 版と同じ `Rdv3Geom.cs` / `docs/ui-ref-geom.json` の実測矩形から組む。ワークシートは
ピクセルに物を置けないので、**セルを十分小さくしてピクセルとして使う**:
列幅を 1 回だけ較正して 1 セル = 4 px にし (実測 `ColumnWidth 0.27`、313 列 × 265 行)、
矩形ごとにその範囲を **結合**して 1 つの部品にする。塗り・罫線・書体は build 時に確定し、
実行時に触るのは名前付き範囲の `Value2` と、選択が移った候補行の塗りだけ。

`build/ui_grid_app.ps1` が描き、`modRdv3Ui` は**アドレスを一切知らない** — 部品はすべて
定義名 (`rdvKeyValue` / `rdvVerdict` / `rdvCand_r_c` …) で書き込む。矩形が動いても VBA は変わらない。

UserForm・ActiveX・Forms コントロール・図形は使わない。ボタンは従来どおりハイパーリンクセルで、
クリックは `Worksheet_FollowHyperlink` から `modRdv3App` に届く。

### 14.1 C# 版と意図的に違うところ

| | 理由 |
|---|---|
| エラー行を**常に確保**し、無いときは空 | 見本はエラー行を差し込んでカードを伸ばすが、シートは再フローできない。エラーのたびに全行の高さを描き直すのは、ホットパスでの全面再フォーマットになる |
| 候補一覧は**行数ぶんの高さを持つ** | 見本は 152 px の枠内をスクロールする。シートに枠内スクロールは無く、シート自身がスクロールする。増えた高さのぶん下の領域が下がる (見本自身の「増えた高さは候補一覧と統合レコードで分ける」規則を、シートで可能な向きに適用) |
| カード高さ 689 → **999 px** | 上の 2 つの合計 |

### 14.2 受け入れ条件

シートは `DrawToBitmap` できないので、C# と同じ ±2px の数値判定は**作れない**。
VBA 版の条件は「列幅を実測で較正したうえで矩形表どおりに配置され、文字切れ・重なりが無いこと」。
判定は実 Excel での確認による。

## 9. 値が無いときの表示

見本は未選択も空欄も一律に「—」で埋めるが、**使い分ける** (オーナー指示)。

| 状況 | 表示 | 理由 |
|---|---|---|
| まだ検索していない / 候補を選んでいない | **空欄** | 副題が「未検索」「未選択（候補 N 件）」と言っている。記号を並べても画面が汚れるだけ |
| 選択済みだが、その項目が台帳で空 | **`N/A`** (薄いグレー・通常太さ) | 「表示しているが値が無い」ことを明示する。実データの太字と区別できる |
| 未選択のときの統合レコードのタグ | **タグごと出さない** | 「番号2 = —」は情報ではない |
| まだ計測していない時間 | **セグメントごと出さない** | 値の無いものに枠だけ残さない |
| 長文ボックス (摘要・備考) | **空欄のまま** | 枠が空であること自体が答えになっている |

## 12. 設定モーダル (`Reader Data Viewer_ver4.html` の実測から再構築)

最初の版は「ラベルとテキストボックスを平らに並べただけ」だった。作り直しは**メイン画面と
同じ手順**で行っている: 見本をブラウザで開き、モーダルの各要素の矩形・書体・色・罫を
数値で読み出し、その表 (`src/app/csharp/Rdv3SetGeom.cs` と
`docs/ui-ref-settings-geom.json`) から画面を組み立て、実物を描いて数値で突き合わせる。

### 12.1 実測した骨格 (モーダル基準・CSS px)

| 行 | 矩形 | 中身 |
|---|---|---|
| ヘッダー | `0.7, 0.7, 1058.7, 60` | 「設定」21/600 ・ 副題 10/400 ・ 右端に閉じる (ゴースト) |
| タブ | `0.7, 60.7, 1058.7, 46` | 16/600 の 3 タブ (間隔 20.4)、選択タブの下に **accent 2px**、右端にファイル名 10/400 |
| 本文 | `0.7, 106.7, 1058.7, 596.7` | 内側 `21.1, 127.1, 1017.9, 558` |
| フッター | `0.7, 703.3, 1058.7, 60` | 面色 **N100** ・ 保存先 11/400 ・ 保存 (primary) / 取消 各 130×31.7 |

監視対象タブは左 300 px の列 (対象リスト → 追加/複製/削除 → 画面から選ぶ → 注記) と、
右 690.7 px の列 (名前 → ウィンドウ → 欄 → 値の取り方/探索範囲 → 中間パス) の 2 段組。
右列は 335.1 px の 2 カラム (溝 20.4)。動作・ファイルタブは 620 px の 1 段組。

### 12.2 判断の根拠 (見本がそう決めていること)

- **濃紺のバーは "ステータスバー" という意味**を持つ。アプリのウィンドウの下端に 1 つだけ
  あって、いま動いている状態を言う。モーダルに状態は無いので**使わない**。見本のフッターも
  N100 + 上に 1px の罫。色を持ってきただけで意味が変わる、という失敗だった。
- **システムの枠を外し、モーダル自身がクロームを持つ** (`FormBorderStyle.None`)。
  見本はブラウザ内のモーダルでタイトルバーが存在せず、カードが自分でヘッダー
  (表題・副題・閉じる)を描いている。それを `FixedDialog` に載せると Windows が
  **もう 1 本のタイトルと 2 つ目の × を重ねる** — 最初に出した版はこれで
  「× が二つ」になっていた。ヘッダーがタイトルバーそのものなので、表題は 1 つ、
  × も 1 つ、**ヘッダーを掴んでウィンドウを動かす** (`Rdv3Dialog.DragZone`)。
  影は `CS_DROPSHADOW` (マネージドのクラススタイル。API 呼び出しではない)。
  ピッカーも同じで、罫より上を掴んで動かせる (対象アプリの上に浮くため必須)。
- **左レールをやめてタブにした**。見本がそう作っている。切り替えは Ctrl+Tab でもできる。
- **見出しは問いを持つ**: 「ウィンドウ — どの画面か」「欄 — どの入力欄を読むか」
  「番号 — 何を検索キーとするか」「監視 — 読み取りのタイミング」。10px の accent に
  下罫。見出しだけ読んで意味が分かる。
- **字は 3 サイズだけ**: 値 13/400、ラベル 11/400、見出し・タグ 10/400 (加えて表題 21/600、
  タブ 16/600)。WinForms 既定のまま置いたものは 1 つも無い。
- **部品は意味で選ぶ**: 1 対 N は**セグメント**、切り替えは**自前描画のチェック**、
  監視対象は名前・有効タグ・*何を指しているか*を並べた**カード** (選択は accent-100 +
  左 2px、メイン画面の行選択と同じ意味)、中間パスは 1 行の**注記 + 控えめな削除**。
- **10–12px の淡色は N700 に落とす**。見本は N600 だが、この描画系では細く沈む
  (6.3 と同じ判断)。

### 12.3 伸び縮みしない — 代わりに全体が縮む

このモーダルは 1060×764 で**詰まっている**: 左列はリスト → ボタン → 注記で本文の最終行まで、
右列も名前 → ウィンドウ → 欄 → 値の取り方 → 中間パスで同じ行まで届く。渡せる余白が無い。
そこで**伸縮させない**。作業領域が設計サイズを収められないとき (125% の 13 インチなど) は
**モーダル全体の縮尺を下げて**収める (`Rdv3Dialog.FitScale`、下限 0.7)。比率も読み順も
そのまま残り、再配置も省略も起きない。

### 12.4 受け入れ検査

`build/test_settings_geometry.ps1`。ウィンドウは**一度も表示しない** (ハンドルだけ作って
`DrawToBitmap`)。製品ソースをそのままコンパイルして実物を描く。

- **忠実度** — 設計サイズ・設計縮尺で、3 ページ + ピッカーの **168 要素**を実測表と数値比較。
  レイアウトが決める成分 (すべての y/h、構造要素の x/w) が **±2px 以内**。
- **健全性** — 拡大率 3 種 × データ 4 種 (見本と同じ 3 件 / 長い値 / 0 件 / 14 件でスクロール)
  × 3 ページ + ピッカー 3 種 = **45 通り**で、**交差 0 / はみ出し 0 / 省略 0 / 枠外れ 0**。

結果は 7 章。

## 13. 要素ピッカー (460 × 292.8、これも実測)

業務アプリの欄を識別子の**手入力**で指定するのは非現実的なので、**指して取る**方式にした。

1. 設定モーダルの「画面から選ぶ」を押す → 小さなパネルが右下に出る (常に手前・「最前面」タグ)
2. 対象アプリの欄に**カーソルを合わせる** → 種類 / AutomationId / クラス名 / 名前 /
   プロセス / 読み取れる値が**リアルタイムで**出る (ラベル 120px + 値、行送り 27.6)
3. **Ctrl + Shift** で取り込む。「この要素を対象にする」ボタンでも同じ。Esc で中止

取り込みでは、その要素からウィンドウまで遡り、**AutomationId を持つ段だけ**を中間パスに
残して、ウィンドウ・中間パス・欄・値の取り方を組み立てる。

使っているのは `AutomationElement.FromPoint` (UIA) と `Cursor.Position` /
`Control.ModifierKeys` (WinForms) だけ。**フックも RegisterHotKey も使っていない**。
