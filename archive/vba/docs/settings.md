# 設定ファイル `ReaderDataViewer.json`

配布は **2 枚**です。

```
ReaderDataViewer.vbs     プログラム (入口。コンソール窓は出ません)
ReaderDataViewer.json    この設定
```

`.vbs` と同じフォルダーに置きます (`.cmd` も同梱してあり、そちらから起動しても同じです)。**無くても動きます**（下に書いた既定値で動作し、
ログにそう残ります）。`-config <path>` で別の場所を指定することもできます。

- `//` 行コメントと `/* ... */` ブロックコメントを書けます。
- 値が範囲外なら**その値だけ**既定に落ちて、理由がログに出ます。ファイル全体は生きます。
- 相対パスは `.cmd` のあるフォルダーからの相対です。
- アプリの右上「設定」ボタンから GUI で編集して、このファイルに書き戻せます。

## VBA 版も同じファイルを読み書きします

`ReaderDataViewer.json` は **C# 版と VBA 版で同じもの**です。形式・メンバー名・既定値・
範囲外の扱いはすべて共通で (`modRdv3Cfg` が `Rdv3Json.cs` + `Rdv3Config.cs` に対応)、
どちらのビルドで書き戻しても、もう一方がそのまま読めます。配布物にはそれぞれ同じファイルが
1 枚ずつ入ります。

VBA 版の設定画面は**別ウィンドウではなくシート**です (画面右上「設定」→ SETTINGS シート)。
中身は C# 版のモーダルと同じ 3 区分 — 監視対象 / 動作 / ファイル。「保存」でこのファイルへ
書き戻し、「取消」でファイルを読み直します。

### VBA 版は `processName` を使いません

`processName` で対象を絞れるのは **C# 版だけ**です。プロセス ID から実行ファイル名を引く
手段が、VBA では WMI しかありません。VBA 版が外部に使ってよい機構は **UI Automation だけ**で、
UIA はプロセス ID までしか出しません (実測: `ProviderDescription` は取得できず、`ClassName` が
実行ファイル名と一致するのはメモ帳のように**たまたま同じ場合だけ**。electron は
`Chrome_WidgetWin_1`、explorer は `Progman`)。

そのため VBA 版では、`processName` を書いた対象は**一致しません**(黙って無視して別の
ウィンドウに接続するより安全なため)。「画面から選ぶ」も `processName` を記録しません。
VBA 版で対象を絞るときは **`className` / `nameLike` / `automationId`** を使ってください。
どれも UIA が直接返す値です。出荷時の既定設定は `className: "Notepad"` なので、既定のままなら
影響はありません。

### VBA 版で 1 つだけ違うこと (監視対象の見つけ方)

C# 版は**フォーカスの有無に関係なく**ウィンドウを探します。VBA 版は探しません ——
Excel 自身の UI スレッドから UIA でデスクトップを歩くと Excel 自身のプロバイダーで
**デッドロックする**という実測があり (`modRdv3Uia` 冒頭)、Win32 も使わない規約のため、
入口は `GetFocusedElement` だけです。

つまり **VBA 版では、対象の欄を一度クリックした時点で接続します**。一度つながれば以後は
保持して監視し続け、複数の対象を同時に見られます。状態行は「対象の欄を一度クリックすると
接続します」「2/3 接続」のように**そのことを正直に出します**。
設定画面の「画面から選ぶ」も同じ理由で、マウスで指すのではなく**対象の欄をクリックした欄**を
見ます。**クリックしても設定は変わりません** —— 押した欄の内容が「いま選ばれているもの」として
表示されるだけで、行に入るのは**「この要素を使う」を押したとき**です (C# 版の
`Ctrl + Shift` / 「この要素を対象にする」にあたります)。**ファイルに書くのは「保存」だけ**で、
「閉じる」でも時間切れでも何も変わりません。目的の欄を探して別の欄をクリックしてしまっても、
設定は無傷です。

やめ方は 3 つあり、どれも同じ結果 (何も採用しない) です。パネルの**「閉じる」**、設定画面の
**「取消」や「戻る」**、そして**設定画面が手前にあるときの `Esc`**。`Esc` は Excel が
キーボードを持っているときにしか届かない (対象アプリを操作している最中は Excel に来ません)
ので、確実なのはボタンのほうです。

## 監視は UI Automation だけで行う

対象アプリの探索・要素の特定・値の取得は**すべて UI Automation** です。ウィンドウハンドル探索、
メッセージフック、キーボード／マウスのポーリングは使いません（アプリ自身のウィンドウの
DPI 設定と、起動用コンソールを隠す 2 か所だけが Win32 です）。

## 監視対象 (`watch.targets`)

**複数指定できます。有効なものは同時に監視され**、最初に確定した番号が検索を動かします。
1 つの対象は次の経路です。

```
window  ->  path[0]  ->  path[1]  ->  ...  ->  field
```

業務アプリの欄はたいてい数階層下（タブ → パネル → グリッド → セル）にあるので、
`path` で段階的に絞ります。各段で指定できるもの:

| メンバー | 意味 |
|---|---|
| `automationId` | アプリが付けている安定した識別子。**あるならこれが最良** |
| `className` | ウィンドウ／コントロールのクラス名 |
| `name` | 完全一致 |
| `nameLike` | `*` `?` のワイルドカード |
| `processName` | 実行ファイル名（`.exe` なし）。**C# 版のみ**（下記） |
| `controlTypes` | `Edit` `Document` `DataGrid` `Pane` `Custom` など |
| `index` | 複数一致したとき何番目を採るか（0 起点） |
| `scope` | `descendants`（既定）または `children` |

`read` は値の取り出し方です。業務アプリの欄は 3 通りに割れます。

| 値 | 使う UIA | 典型 |
|---|---|---|
| `value` | ValuePattern | 一般的な入力欄（既定） |
| `text` | TextPattern | リッチエディット、ドキュメント |
| `name` | Name プロパティ | 読み取り専用のラベル表示 |

### 例: 業務アプリの特定欄

```jsonc
{
  "enabled": true,
  "name": "在庫照会",
  "window": { "processName": "LobApp", "nameLike": "在庫照会*", "scope": "children" },
  "path": [ { "automationId": "tabMain" }, { "automationId": "pnlSearch" } ],
  "field": { "automationId": "txtBarcode", "controlTypes": ["Edit"] },
  "read": "value"
}
```

### 手で書かずに済ませる

この JSON は画面右上の**「設定」**から GUI で編集できます。タブは 3 枚:

| タブ | 中身 |
|---|---|
| **監視対象** | 対象の一覧 (追加 / 複製 / 削除) と、選んだ対象のウィンドウ・欄・値の取り方・中間パス |
| **動作** | 番号の桁数と数字のみ、監視間隔・確定待ち・再接続間隔・候補の表示行数、前面優先 |
| **ファイル** | データ (CSV) フォルダー、統合台帳、ログ |

書き方が分からないときは、**「画面から選ぶ」**を押すと右下に小さなパネルが出ます (C# 版。
VBA 版はシート上の同じ区画です)。

1. 対象アプリの欄に**カーソルを合わせる** → 種類 / AutomationId / クラス名 / 名前 /
   プロセス / 読み取れる値がリアルタイムで表示されます (VBA 版は**クリックした欄**を見ます)
2. **Ctrl + Shift** で取り込み (パネルの「この要素を対象にする」でも同じ。Esc で中止)。
   **VBA 版に `Ctrl + Shift` はありません** —— ボタン (「この要素を使う」) だけです

どちらの版でも、**見ているだけでは何も変わりません**。取り込みで設定欄が変わり、
**ファイルに書くのは「保存」だけ**です。

その要素からウィンドウまで遡り、AutomationId を持つ段だけを中間パスに残して、
ウィンドウ・中間パス・欄・値の取り方を自動で組み立てます。手で書くより確実です。

## そのほかのメンバー

| メンバー | 既定 | 意味 |
|---|---:|---|
| `paths.dataDir` | `data` | CSV 3 本のあるフォルダー |
| `paths.ledger` | `ReaderDataViewer-Ledger.xlsx` | 統合台帳 |
| `paths.log` | `ReaderDataViewer.log` | 実行ログ |
| `key.length` | 8 | 番号の桁数。CSV のキー列の幅・索引・画面の入力欄すべてがこれに従う（次回起動から） |
| `key.digitsOnly` | true | false なら英数字も可 |
| `search.candidateRowsShown` | 10 | 候補一覧に出す最大行数（件数は必ず表示） |
| `watch.pollMs` | 40 | 監視間隔 |
| `watch.stableMs` | 120 | この時間だけ値が変わらなければ確定 |
| `watch.rebindMs` | 400 | 未接続の対象を探し直す間隔 |
| `watch.preferFocusedWindow` | true | 同じ条件の窓が複数あるとき前面を優先 |
| `jobs.checkTimeoutMs` | 180000 | 起動時の更新確認ジョブの上限 |
| `jobs.searchTimeoutMs` | 30000 | 検索ジョブの上限 |
| `jobs.saveTimeoutMs` | 60000 | 処理済み保存ジョブの上限 |
| `jobs.markOverdueMs` | 180000 | 保存が長引いていると告げるまでの時間 |
| `jobs.pumpMs` | 1000 | 画面側の見張り間隔 |

`paths.*` と `key.length` の変更は**次回の起動から**有効です。台帳と CSV は起動時に読み、
そのとき `key.length` を**キー列の幅**として使うためで、動作中に桁数だけ差し替えると
画面が受け付ける番号を、すでに出来ている索引が答えられなくなります。
`key.digitsOnly` はこれに含みません（字種は索引の作りに関係しないため、他と同じく即時です）。
それ以外は設定ダイアログの保存で**即座に反映**されます（監視は張り直します）。

`watch.targets` を書いた場合、**書いたとおりに監視します**。無効 (`enabled: false`) にした
対象も設定として保持され（一覧に残り、次の保存でも書き戻されます）、全部を無効にすれば
何も監視しません。そのとき画面は**「監視対象なし」**と出ます —— 「メモ帳を待機中」ではありません。
設定でそう決めたのであって、開いていないアプリを待っているのではないからです。
内蔵の既定（メモ帳）が出てくるのは、設定ファイルが無いか読めないか、
`watch.targets` を書いていないときだけです。ウィンドウか欄のどちらも絞れていない対象は、
どの画面にも一致してしまうので監視せず、理由をログに残します。
