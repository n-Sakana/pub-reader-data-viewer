Reader Data Viewer

別のアプリの画面に出た番号を読み取り、複数の CSV から作った台帳を引き、「処理済」の印を仲間と共有する Windows アプリです。

  • Windows 上で単体で動く（インストール不要、Excel 不要、ネットワーク接続なし）
  • データの扱い方と画面の並びは設定ファイル 1 枚（settings.json）で決める
  • 台帳は共有フォルダーの Excel ファイル 1 本。複数の PC から同じ 1 本を使う

1何をするアプリか

現場では、別のアプリの入力欄に番号が入ります（バーコードなどの読み取り機や手入力）。このアプリはその番号を読み取り、 手元の台帳から該当する行を探して画面に出し、確認した行に「処理済」の印を付けます。印は自分の PC にいったん控えられ、 「送信」を押したときに共有の台帳へ書き込まれて、ほかの人の画面にも伝わります。

1読む設定した別アプリの入力欄を見張り、8 桁の番号が入ったら自動で検索します。画面の検索欄に直接入力もできます。
2引く複数の CSV を結合して作った「統合台帳」から該当行を探します。1 件ならそのまま表示、複数なら候補一覧から選びます。
3印を付けて送る表示中の行を「処理済」（または「未処理」に戻す）にして手元に控え、「送信」で共有台帳へ反映します。

台帳の元になる CSV、結合の仕方、画面に出す項目、判定（OK / NG）の規則、作業状態の名前は、すべて設定ファイルに書きます。 プログラムには「どの列を」「どう結合するか」といった業務の判断が入っていません。同梱の設定とデータは色を抜いたサンプル （表A / 表B / 表C、SAMPLE-A-0000001 のような値）で、現場ではその部分を自分の CSV と画面に置き換えます。

2毎日の使い方

起動する

ReaderDataViewer.vbs をダブルクリックします（コンソール画面を見たいときは ReaderDataViewer.cmd）。 起動すると設定ファイルと CSV を読み、保存済みの台帳と CSV の内容を突き合わせます。CSV に変更があれば「更新しますか」と 尋ねます。準備ができるとステータスバーの左端が「監視中」になります。

番号を読む

設定した別アプリの入力欄（同梱の設定ではメモ帳の本文）に 8 桁の番号が入って少し落ち着くと、自動で検索します。 同じ番号が続けて 2 回読まれても、欄が空にならない限り 2 回目は検索しません。画面の「番号1」欄に入力して 「検索」（Enter）を押しても同じです。番号の形が違うと「番号1 が形式 … に一致しません」と出ます。 見張る窓がまだ無いときはステータスバーに「メモ帳 を待機中」のように出て、窓が開くと自動でつながります。

結果を見る

  • 1 件 — その行の項目（番号、表A の項目、メモ、備考）が画面に並び、判定の帯に OK / NG / 未定義 が出ます。 別アプリから読み取った番号で 1 件だけ当たったときは、確認なしに自動で「処理済」になります。
  • 複数件 — 候補一覧が開きます。行を選ぶまで印は変わりません。閉じれば未選択のままです。 別アプリから読み取った番号のときは、選んだ行が自動で「処理済」になります。
  • 0 件 — 「見つかりません」と出ます。印は付きません。

判定は、設定した列の値を規則（値の一覧、正規表現、空欄）に上から当てて決めます。どの規則にも当たらなければ「未定義」、 列そのものが台帳に無ければ「エラー」で、どちらも OK にはなりません。

印を付ける

「処理済」ボタンを押すと確認が出て、承諾すると手元の控えに保存されます。すでに処理済の行は、同じボタンで 「未処理」に戻せます。控えた件数は「未送信 N 件」に赤字で出ます。保存の途中は、次の印の変更・送信・更新と終了を 受け付けません。

送信する

「送信」を押すと、手元の控えを共有台帳へ書き込みます。処理済にした行も、未処理に戻した行も、いまの値がそのまま 送られます。送信後も行は凍りません。戻したければ番号をもう一度引いて未処理にし、また送信します。 台帳の行が消えていたり中身が変わっていたりして当てられなかった変更は、一覧で知らせて手元に残します。

終了する

窓を閉じます。保存や送信の結果が出るまでは閉じられません（「書き込み中です」と出ます）。未送信の控えは 次回の起動で戻ってきます。

3データと台帳

取り込むデータdata\ の CSV（同梱: 表A・表B・表C と削除指定 1 本）
→
処理内容設定に並べた表操作（結合、マージ …）
→
統合台帳ReaderDataViewer-Ledger.xlsx（共有フォルダー）

台帳は毎回作り直すのではなく、育てます。CSV が新しくなったら「レコード更新」で差分を当てます。マージの規則は 3 方向で、元（CSV）にだけある行は追加、両方にある行は CSV 側の列だけ更新、台帳にだけある行は保持 （設定で「削除」も選べます）。作業状態の列はアプリが持つ列なので、マージで消えません。 CSV 側の中身が変わった行は、設定に従って印を「未処理」へ戻すか、そのまま保つかを選べます。戻った行は一覧で知らせます。

下部の 4 つのボタンでできること:

ボタン何をするか
テーブル出力統合台帳から、選んだ項目だけを CSV に書き出します（既定で data\export-日時.csv）。
レコード更新設定に書いた更新ジョブを表示し、実行すると CSV を読み直して台帳へマージします。
レコード削除設定に書いた削除ジョブを表示し、実行すると指定ファイルに載った行を台帳から取り除きます。
設定場所（CSV フォルダー・台帳・ログ）、番号の形式、監視対象を変えます。

更新と削除のダイアログは「取り込むデータ」「処理内容」「書き出し先」の 3 枠で、実行前に分かることだけを出します。 処理内容の行は設定から機械的に作られ、操作（結合 / 抽出 / 削除 / 追加 / 更新 / 選択 / 計算 / 集計 / 並べ替え / 重複除去 / マージ / 置換）、対象、キー、条件、出力の名前が並びます。

CSV は厳格に読みます。列数がヘッダーと違う行、引用符 " で始まる列、タブや改行などの制御文字を含む行、 キーが空・幅違い・ASCII 以外の行、同じキーが 2 行にある表は、ファイル名と行番号を挙げて止まります。 黙ってずらしたり飛ばしたりはしません。文字コードの不一致だけは止めず、更新・削除ダイアログの「検証」列に 「文字コード不一致（N 行目）」と出して続けます。

4複数人で使う

統合台帳は共有フォルダーに 1 本だけ置き、それぞれの PC で同じアプリを動かします。手元の控え（未送信の印）は 各 PC の中にあり、共有台帳には「送信」「レコード更新」「レコード削除」のときだけ書き込みます。

  • 順番待ち — 書き込む前に台帳の隣にロックファイルを作ります。誰かが書いている間は 「○○（PC 名）が N 分前から台帳を使用しています。空くまで待ちます。」と出て、空いたら続けます。
  • 最新を読み直してから書く — ロックを取ったあとに台帳を読み直し、自分の変更だけを当てて、 一時ファイルへ書いてから置き換えます。途中で止まっても台帳が半端になることはありません。
  • 知らせる — 書き終えると版を記した小さなファイルを更新します。ほかの PC は数秒おきにそれだけを見て、 版が進んでいれば台帳を読み直します。送信なら「○○ が N 件を処理済、M 件を未処理にしました」と出ます。 レコード更新なら「切り替えますか」と尋ね、印が戻った行があれば一覧で示します。
  • Excel で開いている間 — 誰かが台帳を Excel で開いていると書き込めず、「書き込めませんでした」と出ます。 控えは残るので、閉じてもらってから送り直します。

同じ PC で同じ台帳を 2 つ同時に開くことはできません（「すでに起動しています」）。

5設定

設定は settings.json 1 枚です。6 つの部分からなり、コメント（// と /* */）を書けます。

部分中身誰が変えるか
pathsCSV フォルダー、台帳、ログの場所人、または「設定」ボタン
search番号の形式（正規表現）、候補一覧に出す最大行数人、または「設定」ボタン
watch見張る窓と入力欄（UI Automation の条件）人、または「設定」ボタン
jobsバックグラウンド処理の時間上限、共有ファイルの確認間隔人
dataCSV の一覧とキー、表示名、更新／削除ジョブ、台帳の列と検索列人
screen画面の部品と並び、値の取り方、判定規則、作業状態、候補一覧の列人

「設定」ボタンが書き戻すのは paths / search / watch の 3 つだけで、ほかの部分と コメントは 1 バイトも変わりません。見張る欄は「画面から選ぶ」で指定できます。目的の欄にマウスを合わせて Ctrl+Shift を押すと、その欄までの経路が自動で設定に入ります。

壊れた設定では起動しません。知らないメンバー（誤字）、型や範囲の違う値、存在しない列や状態の名前が 1 つでもあれば、ファイル名・行・理由を出して止まります。「直したつもりが効いていない」状態を作らないためです。

6試してみる

同梱サンプルの表A・表B・表Cは各 1,000 行です。表Bの空の識別子 10 行を設定どおり除外するため、 統合台帳は 990 行になります。表Cには表Bから参照されない 10 行も含まれます。 削除指定は delete.csv 1 本の key2 と b_ref を読み、2 条件とも一致するレコードだけを削除します。 検索を試すときは、番号1 に次の 8 桁を入れます（完全一致）。

    7しないこと

    • 読み取り機そのものには接続しません。設定した別アプリの入力欄に入った値を、画面から読むだけです。別アプリへ書き込みません。
    • 業務の判断（どの列で照合するか、何を OK とするか、どの行を消すか）を持ちません。すべて設定に書きます。
    • 引用符で囲った CSV、列数の揃っていない CSV、制御文字を含む CSV は読みません。直してから読ませます。
    • Excel の行数の上限（約 104 万行）に近づいたときの分割は行いません。
    • ネットワークへは接続しません。共有フォルダーの台帳も、普通のファイルとして読み書きするだけです。

    ここから先は、ソースコード（src/csharp の 19 本と settings.json）を読んで書いた中身の説明です。既定では折りたたんであります。

  ReaderDataViewer.cmd          同じ中身。コンソールを見たいとき

    CSV の読み方と台帳の形
    • CSV はファイル全体をバイト配列に読み、行ごとに列数・引用符・制御文字（0x00〜0x1F）・キー列（空、幅、ASCII）を検査します。 値はそのときは復号せず、必要になったセルだけを指定の文字コードで復号します。
    • 指定の文字コードで復号できないバイトがあるかを読込時に一度だけ厳格に調べ、最初の行番号を覚えて「検証」列に出します。処理は続けます。
    • 表のキー列は一意でなければならず、重複は行番号を挙げて止まります。
    • 台帳の 1 行はメモリ上ではタブ区切りの文字列です。列名は CSV のヘッダーそのもので、data.ledger.columns.source の順です。
    • xlsx はシート LEDGER 1 枚。先頭列が作業状態（見出しは screen.workState.store.column）、以降が台帳列。 セルはすべて文字列（先頭のゼロが残る）。読むときは共有文字列やセル座標付きの形も受け付けるので、Excel で保存し直した台帳も読めます。
    • 台帳を読んだ直後に、見出し行が定義と一致すること、識別列（data.ledger.identity）が空でも重複でもないこと、 セルにタブが無いことを確かめ、違えばファイル名と行番号を挙げます。
    ジョブ（表操作）の語彙

    ジョブは入力（表、または 1 列の外部ファイル）と順序付きの段（steps）です。段の出力名は次の段の対象になります。値の種類は 表、行集合（ある表から選んだ行）、台帳の 3 つで、種類が合わない組み合わせは起動時に拒否します。

    operation入力出力
    join2 表、keys、condition: match（内部）/ left（左外部）/ full（完全外部）表
    append同じ列名・順序の 2 表表
    extract表と where、表と表 + keys（match / exclude）、行集合 2 つ（either / both / exclude）行集合
    select1 表と columns（as で改名）表
    calculate1 表、column、expression表
    aggregate1 表、groupBy、aggregates（sum / count）表
    sort1 表、orders（ascending / descending、text / number）表
    distinct1 表、同一判定の columns表
    update表と、その表からの行集合、set表
    delete表と、その表からの行集合表
    merge元表と台帳、keys、sourceOnly（add / ignore）、both（update / keep）、targetOnly（keep / delete）台帳
    replace元表と台帳、keys台帳

    左外部結合だけを重ねてマージ／置換で終わる更新ジョブは、バイト索引による高速経路で実行します（意味は同じ）。 それ以外の組み合わせは汎用の実行器で動きます。where の演算子は equals / notEquals / contains / startsWith / endsWith / empty / notEmpty / greater / atLeast / less / atMost、式は列・数値・シングルクォートの文字・丸括弧と + - * / だけです。

    共有ファイルと手元の控え
    • 手元の控え — %LOCALAPPDATA%\ReaderDataViewer\pending-<台帳パスのハッシュ>.dat。行の識別値、保存する値、 その行の内容のダイジェスト（SHA-256）を持ちます。送信時にダイジェストが合わない行は「中身が変わっています」として残します。 共有台帳と同じ値へ戻した変更は控えから消えます。
    • ロック — 台帳の隣の <台帳名>.lock を CreateNew で作れた側が書き手です。中に PC 名・ユーザー名・時刻を 持ち、待つ側はそれを表示します。書き終えたら消します。
    • 符丁 — <台帳名>.version。版番号、書いた人、種類（update / send）、件数を 1 行で持ちます。各 PC は jobs.markerPollMs（既定 3 秒）ごとにこのファイルだけを見て、版が進んだら台帳を読み直します。
    • 書き込み — 台帳・控え・符丁のどれも、一時ファイルに書いてから File.Replace で置き換えます。 読む側は置き換えを妨げない共有モード（ReadWrite | Delete）で開き、読み始めた版を最後まで読みます。
    アプリの状態遷移とスレッド

    UI スレッドは重い処理を持ちません。CSV の読込、索引、比較、検索、xlsx の読み書きは 1 本の worker スレッドがジョブ列の 順に実行し、結果だけを UI へ戻します。ジョブには run ID があり、待っている ID と違う結果（タイムアウト後に遅れて届いたもの、 検索の重ね打ち）は捨ててログに残します。

    状態語: 起動中 → 更新を確認中 →（確認）→ 台帳を更新中 → 監視中。差分が無いか承諾しなければ保存済みの台帳のまま監視中、 台帳が無く作らないなら「台帳がありません」。送信中、レコードを削除中、台帳が空くのを待機中、台帳を読み直し中、 {状態}を保存中 の各状態では次の操作を受け付けません。

    作業状態の保存・送信・更新・削除は「結果が確定するまで終了を拒否」します。確定（成功でも失敗でも）したら解除します。

    ログと検査

    実行ログは paths.log（既定 ReaderDataViewer.log、.vbs の隣）にタブ区切りで 1 行ずつ追記します。 起動時の設定内容、読込・索引・結合・比較・保存の所要時間、検索の件数と時間、監視対象からの検出、ロックの取得・待機、 符丁の観測、エラーが残ります。

    build.bat                                                   配布物を dist\app-csharp に作る
powershell -File build\compile_check.ps1                    パッカーと同じ形でコンパイルだけ行う
powershell -File build\test_settings_contract.ps1           定義の読込みと拒否、マージ規則、送信の解決 (209 件)
powershell -File build\test_settings_geometry.ps1           標準部品の構成 (36 件)
powershell -File build\test_samples.ps1                     見本定義 5 組を製品コードに通す (158 件)
powershell -File build\test_exit_guard.ps1                  実配布物を起動し、検索・保存・送信・競合・終了を通す (35 件)

    検査はどれも窓を画面に出しません（画面外に置くか、DrawToBitmap で描きます）。
