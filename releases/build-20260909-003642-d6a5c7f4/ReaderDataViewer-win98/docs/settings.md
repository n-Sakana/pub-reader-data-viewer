# settings.jsonで変更できる範囲と注意点

## 設定形式

本アプリ独自の **schema 3** を使用します。ファイル名は `settings.json` ですが、`//` と `/* ... */` のコメント、末尾カンマを許可するJSONCです。標準JSON専用の検査ツールではコメントがエラーになります。未知の項目・不正な型・不明な参照先はアプリ側で拒否します。修正版では未終了コメント、不正な数値表記、生の制御文字、不正なサロゲート、128段を超えるネスト等も拒否します。

設定は任意のプログラムを記述する場所ではありません。以下の定義済みの機能を組み合わせます。完全な項目定義は同梱設定のコメントと `src/Rdv3Config.cs`、`Rdv3Data.cs`、`Rdv3Screen.cs`、`Rdv3Process.cs` を参照してください。

| 設定 | 対応範囲 | 主な制約 |
|---|---|---|
| `paths` | データ、共有台帳、ログの場所 | 台帳は`.xlsx`。入力・ログ・台帳・プログラム等の衝突は禁止 |
| `search` | 入力形式の正規表現、候補表示件数 | キー全体に一致させる。正規表現タイムアウト250ms、バックエンド入力上限4,096文字 |
| `watch` | UI Automation監視先、読取方法、安定判定、ポーリング | Windows・対象アプリへの依存あり。読取権限・対象の構造・フォーカス等は実機確認 |
| `jobs` | 時間監視、ロック再試行、変更検知の間隔 | OSの同期ファイルI/Oを強制終了する期限ではない |
| `data.tables/types/labels` | 複数CSV／XLSX、キー検証、数値／日付の扱い、表示名 | 列挙した全テーブルを起動時に確認。任意の外部DB接続はない |
| `data.jobs` | `join`, `extract`, `delete`, `append`, `update`, `merge`, `replace`, `select`, `calculate`, `aggregate`, `sort`, `distinct` | 入出力の種類・列参照・結果形状を満たす必要がある。任意SQL／C#実行ではない |
| `data.ledger` | 識別キー、検索対象列、保存列、入力変更時の作業状態方針 | 識別キーは全行で一意かつ安定。保存先はアプリ管理台帳 |
| `screen` | 表示項目、候補一覧、判定、レイアウト、ボタンとジョブの対応、作業状態 | 部品の種類は定義済み。自由なセル編集画面ではない |

## パスと配置

`paths.dataDir`、`paths.ledger`、`paths.log` の相対パスはアプリフォルダーを基準に解決します。テーブルとジョブ入力の相対ファイル名は `dataDir` が基準です。絶対パスも利用できます。共有運用では全PCの `ledger` を同じ共有ファイルへ向け、ログをPC別に分けます。

次は`paths`部分だけの例です。JSON文字列のバックスラッシュは二重にします。

```json
"paths": {
  "dataDir": "data",
  "ledger": "\\\\server\\share\\ReaderDataViewer-Ledger.xlsx",
  "log": "data/ReaderDataViewer.log"
}
```

本アプリのパス保護は通常の絶対パス比較です。別名共有、ハードリンク、シンボリックリンク等を完全に同定するセキュリティ境界ではありません。同一ファイルへ異なる名前でアクセスする構成は避けてください。

## 入力CSVとキー

修正版はカンマ区切り、引用符、引用符内のカンマ・改行、二重引用符、CRLF／LF／CR、宣言された文字コードに対応する読み込み経路を持ちます。一般的な引用符なしUTF-8／Shift-JIS等は従来の高速経路を残しています。引用符付きCSVやUTF-16／UTF-32等は文字として解析する経路を使うため、速度・メモリー特性は同じではありません。

`data.encoding`は全CSVの共通設定です。BOMがある場合は宣言した文字コードとの一致が必要です。異なる文字コードのCSVを無条件に混在・自動判別する機能ではありません。不正なバイト列や引用符、列数の不一致はエラーにします。ヘッダーのみの表は0件として扱いますが、ヘッダー自体の欠落・重複・空見出しはエラーです。

キー検証の既定はASCII・固定長・重複エラー・空キーエラーです。可変長の日本語識別子には、テーブル定義の一部として次のように指定します。

```json
"keyValidation": {
  "characters": "unicode",
  "length": "variable",
  "duplicates": "error",
  "empty": "error"
}
```

`duplicates: "distinct"` は同じキーの最初の行を採る動作であり、値を合算したり重複レコードをすべて保持したりする指定ではありません。`empty: "skip"` は空キー行を取り込みません。同梱 `tableB.csv` には1,000行中10行の空キーがあり、この指定により有効キーの行は990行です。これは元データと元設定にある仕様であり、今回削除した行ではありません。

検索パターンはテーブルキーの検証とは別です。可変長やUnicodeのキーを認めても、数字専用の検索パターンのままでは検索できません。例として、先頭英字と数字6桁なら `"pattern": "[A-Z][0-9]{6}"` のように指定します。修正版は全体一致なので、部分一致を意図していた設定は見直してください。`.*`を含めて意図的に全体を記述することは可能です。

キー内の制御文字は原則エラーです。非キーのタブ等の一部制御文字は警告の上で`?`に置換されます。CSVの引用符内のCR／LFは保持します。XLSX入力では内部行へ変換する前に一部文字を正規化するため、キーを含めて完全なバイト保存を保証する形式ではありません。

## XLSX入力と共有台帳は別の扱い

入力XLSXは、`workbook.xml`上で最初に列挙されたシートを読みます。物理ファイル名`sheet1.xml`固定ではありません。任意シート名を選ぶJSON項目は未実装です。最初のシートをデータ表にするか、入力用に単一シートのファイルを用意してください。最初がグラフシート等の場合はエラーです。非表示シートでも先頭にあれば対象です。

数式を再計算する機能やExcelの表示書式を再現する機能はありません。数式の保存済み値を読み、保存済み値がない数式やエラーセルは拒否します。保存済み値が古いかどうかは判定できません。日付セルのシリアル値を任意の`yyyyMMdd`へ自動変換することもしません。コード番号は入力元でも文字列にし、Excel側で失われた先頭ゼロは復元できないものとして扱ってください。

共有台帳はアプリ専用の`LEDGER`シート1枚だけにします。修正版は追加シートや非空の余分な列を拒否します。台帳更新は単一シートを再構成するため、書式、数式、図形、コメント等を編集しても保存される前提にはできません。保存列・状態・識別キーの一部契約が異なる修正版同士は、台帳内の契約ハッシュにより読み書きを止めます。旧台帳には契約ハッシュがないため、ヘッダー照合だけでは意味の一致を証明できません。

## データ型と処理の意味

数値は不変カルチャーの数値表記を前提とし、小数点は`.`を使用します。CSVの区切りカンマと数値の桁区切りを混同しないでください。日付は`data.types`の`format`に合った文字列が必要です。画面での表示書式の変更と、入力データの型検証は同じ設定ではありません。

最初の`kind: "update"`ジョブが起動時の確認対象です。ジョブの並べ替えだけでも起動時に行う処理が変わります。削除、置換、`targetOnly: "delete"`、入力変更時の状態リセットなどは、正しく設定されていても意図的にデータや作業状態を減らす操作です。検証用台帳で件数と対象を確認してください。

同梱の削除ジョブは、`delete.csv`の`key2`列の集合と`b_ref`列の集合をそれぞれ検索し、その**レコード集合の積集合**を削除します。**CSVの同一行にある2列の組の一致とは異なります。** 同梱データでは両者の一致件数は342件ですが、値を組み替えた別データでは結果が違い得ます。業務上の正しい削除条件が不明なため、この既存仕様は勝手に変更していません。組での一致が必要な用途では、一意な複合キーを入力側で用意するなど、条件の設計が必要です。

## 作業状態と自動検出

アプリ管理の作業状態は1列です。複数の状態と遷移を定義できますが、同一状態から複数の別操作を選ぶ一般的なワークフローエンジンではありません。遷移の分岐、複数人承認、権限制御、変更履歴、複数の独立した編集列は追加実装が必要です。

修正版の既定値は以下です。既存の`workState`定義に1項目を加えています。

```json
"trigger": "manual"
```

`automatic`にすると、外部画面からの検出を契機に自動変更する従来の動作を有効にします。監視値が同じままの場合は、常に連続して再検出されるわけではありません。アプリ側のクリア操作は外部アプリの値を消さず、検出器を無条件に再発火させる操作でもありません。処理中に検出値が一時的に現れて消えた場合、全読み取りを保存するイベントキューや件数保証はありません。

設定画面は主としてパス・検索・最初の監視対象を編集する補助画面です。複数対象や`enabled`等はJSONで確認してください。無効な既存対象を選び直しても、元の`enabled: false`は維持されます。これは勝手に監視を有効化しないための既存挙動です。

## 設定の保存・切替

設定画面を開く際はディスク上の設定を再読込し、保存前に読取時のハッシュを照合します。他の設定画面やテキストエディターが先に保存していた場合は上書きを拒否します。アプリ同士の保存は`.edit.lock`でも排他します。ただし、ロックを無視する外部エディターが照合直後に変更する競合までは完全に防げません。

監視・検索・時間設定の一部は実行中に適用されますが、保存先パス、データ定義、画面定義等は再起動が必要です。JSONファイルを外部編集しただけで全設定が自動的に切り替わることはありません。設定構造を変更するときはアプリを閉じて編集し、全PCで同じ契約を使って起動し直してください。

表示ラベルのない保存列もCSV出力候補に含めます。ただし未保存の入力列を出力する指定ではありません。CSVは単なる文字列データなので、Excelで直接開くと先頭ゼロや日付が自動変換され得ます。必要な列を文字列として取り込んでください。数式無効化はその自動型変換を防ぐ機能ではありません。
