# 複数人・複数PCで同じ台帳を使う場合

## 判定と前提

修正版は共有ファイルの排他に加え、変更前の状態との照合を導入しました。ただし、**実際のWindows・SMB・複数PCでの試験は今回未実施**です。ファイルサーバー／NASが必要なファイルロックと置換を正しく提供するか、ネットワーク断や権限変更から復旧できるかは利用環境で確認してください。

同じPC上の複数スレッドを使う回帰試験コードも同梱していますが、それも今回の環境では未実行であり、まして別PCのネットワーク試験の代わりにはなりません。

## 配置

アプリと設定は各PCのローカルフォルダーに置きます。共有するのは、全PCから同一のパスで開く`paths.ledger`の台帳と、その隣の`.lock`、`.version`です。例えば、台帳が`Book.xlsx`なら、付随ファイルは`Book.xlsx.lock`と`Book.xlsx.version`です。これらを別のフォルダーに分離しないでください。

全PCを同じ修正版へ揃え、保存列・識別キー・状態の保存値・入力変更時の状態方針・業務ジョブを一致させます。台帳内の契約ハッシュは構造の一部の違いを検出しますが、業務設定の全項目を同一と証明するものではありません。

利用者には台帳の読み書きだけでなく、同じディレクトリーでの一時ファイル作成・置換・削除と、付随ファイルの操作が必要です。実際の権限は管理者に確認してください。ログはローカルまたはPC別ファイルに分けます。共有ログの同時追記について完全な収集・監査保証はありません。

同一ファイルを共有名の別名、ドライブ文字とUNCの混在などで参照しないでください。ローカル未送信データの識別には台帳のパスを使用するため、名前を変えると別台帳として扱われる場合があります。異なるWindowsユーザー、異なるPCの未送信データは別々です。

## 送信処理

作業状態の変更はローカルへ保存します。送信時には次の順に確認します。

1. 台帳の共有ロックを取得し、ロック内で最新の台帳を読み直します。
2. 未送信変更ごとに、識別キー、レコード内容のSHA-256、変更前の共有状態を照合します。
3. まだ変更可能な行だけを反映し、一時XLSXから共有台帳を置換します。変更通知を書き、反映済みのローカル変更を取り除きます。

別行の変更は最新台帳に合流させます。同一行でも共有状態が既に送信したい値なら反映済みとして処理し、再度状態変更件数を増やしません。行が消えた、内容が変わった、他の状態になった、旧形式で変更前が分からない、という場合は未送信として残し、理由を表示します。

競合一覧からの破棄はローカル未送信データだけを対象にします。通常のOK／Escでは保持し、破棄は追加確認とバックアップ付きです。競合を無視する「強制上書き」は設けていません。最新の行を確認し、不要な旧変更を破棄した上で作業し直してください。

未送信データの場所はおおむね`%LOCALAPPDATA%\ReaderDataViewer\pending-<台帳パスのハッシュ>.dat`です。`.session.lock`はそのローカルデータの同時使用を防ぐためのファイルで、終了後もファイル名自体は残ります。**残っているだけで異常ではありません。** 保有中のOSハンドルを排他に用います。

## 更新・削除・読み直し

入力表から台帳を更新する場合、確認時とロック取得後とで既存台帳の内容が変わっていれば中止し、再確認が必要になります。作業状態だけの変化は最新値を基に処理します。ただし`onSourceChange: "reset"`等で定義したリセットは、業務設定に従う意図的な変更です。

共有版の変更は`.version`に加え、台帳の更新時刻とサイズでも検知します。版番号が前より小さい復元ファイルも、書込者と時刻の違いを含めて扱います。確認画面・保存中には台帳を勝手に切り替えません。読み直し失敗時には直前の有効な表示を残すか、利用不可状態にします。

これは常に最新の共有内容を画面に即時表示する保証ではありません。切替を拒否したPC、ネットワークに接続できないPC、読み直し待ちのPCには古い状態が残り得ます。CSV出力にもそのPCの表示スナップショットと未送信状態が使われます。

## 旧版からの移行

**全PCを停止した状態**で、共有台帳、付随ファイル、設定、各PCの`pending-*.dat`をバックアップします。旧版のまま正常に送信できる未送信分は、業務確認の上で先に処理しておくと移行しやすくなります。未送信ファイルを手編集してヘッダーだけ変えないでください。

旧形式`RDV-PENDING-1`は読み込めますが、変更前の状態が記録されていません。共有状態が既に希望値なら反映済みとして整理でき、それ以外は自動送信せず旧形式の未照合変更として残します。担当者が内容を確認して破棄・再操作してください。修正版で保存した`RDV-PENDING-2`は旧版では読めません。**旧版への単純な上書き戻しはしないでください。**

既存台帳に契約情報がなければ、ヘッダーや状態値等を照合して読み込みます。新たに台帳を書き込む際に契約ハッシュを追加します。旧版はその追加情報や新しい競合検査を理解しないため、新旧混在での安全性はありません。列名が同じでも意味が違う既存台帳について、意味の一致を自動的に保証する仕組みではありません。

列構成や識別キーを変える際は、同じ台帳ファイルを別定義で開いて無理に続行せず、バックアップ・データ移行・全PCの定義切替を行ってください。

## 避ける構成と残存制約

OneDrive・Dropbox等によるローカル複製の同期、オフラインファイル、異なる場所に置いたコピーの後同期は、1つの共有ファイルの同時排他とは別物です。この用途の安全性は提供していません。動作中のExcel直接編集、ロックを無視する別プログラムの書き込み、旧版との混在も対象外です。追加シートを持つ台帳は修正版で拒否します。

台帳と`.version`とローカル未送信ファイルの更新は**1つのトランザクションではありません**。XLSXが保存できた後で通知やローカル整理に失敗する場合があります。再送時の反映済み判定と更新時刻・サイズ検知で一部を補いますが、電源断・共有断・同じサイズと時刻への復元などを含む完全な障害回復は保証できません。

状態値が「A→B→A」と戻る経過（ABA）、同一識別キーで同内容の行が削除後に再作成される経過は、この方式だけでは検知できません。識別キーを再利用しないことが重要です。厳密な版管理、監査証跡、承認権限、オフライン編集、常時高頻度の同時編集が必要な運用には、サーバーでのトランザクションと行版管理等の追加設計が必要です。

時間設定は主に遅延の通知・古い検索結果の破棄に使われます。同期OS I/Oを期限どおりに中断する機能ではありません。共有障害で保存処理が戻らなければ、終了待ちが長引く可能性があります。定期的な変更検知I/Oはワーカーへ移しましたが、全てのI/OがUIスレッド外になったわけではありません。

## 障害時の確認

送信エラーになっても、共有台帳が絶対に未変更とは限りません。まず共有ファイルと未送信ファイルを保全し、現在の行と状態、ログを確認します。台帳が既に希望状態なら再送が反映済み判定になる設計です。

読み込めない台帳を「新規」として置き換えないでください。既存台帳の退避・復元は全PC停止後に担当者が行います。`.lock`を手動で消す前に、所有者と動作中プロセス、共有接続を確認します。古いタイムスタンプだけで処理終了とは判断しないでください。

## 実機受入試験

本番データを複製した専用共有フォルダーを用意し、本番のパスを設定しない検証用アプリ2台で実施します。最初に各PCで`build.bat compile`と`build.bat test`が成功することを確認してください。

| 試験 | 操作 | 期待する確認 |
|---|---|---|
| 異なる行 | PC-A/Bで別行を変更してほぼ同時に送信 | 両方が残り、他行の状態や内容が失われない |
| 同一行・同じ希望値 | 両PCから同一行を同一状態へ送信 | 2回目を反映済みとして扱い、二重計上しない |
| 同一行・異なる希望値 | 3状態の検証設定等で、同じ変更前から別状態へ送信 | 後続は競合になり、先行状態を上書きしない |
| 内容の変更・削除 | Aに未送信を残してBで対象内容を更新／削除 | Aの変更は未照合として残る |
| 更新承認中の他者更新 | Aの確認画面中にBが台帳内容を更新 | Aの古い承認内容を無条件反映しない |
| 長時間ロック | Aでロック保持中にBが待機。検証用に古い時刻も用いる | 有効なロックを経過時間だけで破らない |
| 保存途中の共有断 | 置換前／後、通知前／後の各段階で検証用接続を遮断 | 旧版・新版、未送信の残り方を確認し、エラー後の再送を検証 |
| Excel・権限 | コピーの台帳をExcelで開く／更新権限を外す | 誤って再作成せず、失敗を表示し未送信を保全 |
| 旧形式・移行 | V1未送信を用意して起動・送信 | 未照合を黙って上書きせず、確認して整理できる |
| 異なる設定 | 保存列、識別キー、状態保存値を1台だけ変更 | 契約情報のある台帳で不一致を拒否 |
| UI操作 | 連続検索、クリア、入力変更、IME、候補選択中の他者送信 | 古い対象へ誤って作業状態を適用しない |
| 自動監視 | 対象切替、対象無効、同一キー、処理中検出、manual／automatic | 業務として意図した検索・状態変更だけが起きる |
| 再起動・復元 | 各PCを終了・再起動し、版の古い台帳コピーへ復元 | 未送信の保全、変更検知、再送の扱いを確認 |
| 規模・表示 | 実データ最大件数、DPI、フォント、日本語IME、対象アプリ版 | 待ち時間、メモリー、画面の崩れ、検出漏れを評価 |

この表は期待値と試験手順であり、実施済み結果ではありません。サーバー名、OS、WebView2 Runtimeの版、ファイルシステム、利用者、操作時刻、台帳とログの保全先も記録してください。
