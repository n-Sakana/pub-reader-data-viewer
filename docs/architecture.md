# C# 版アーキテクチャ

Reader Data Viewer の現行製品は C# / WinForms 版です。CSV または Excel の表を読み、JSON に並べた一般的な表操作で
表を作り、検索・表示・判定・作業状態の保存を行います。入力表が何か (`data`) と画面に何を出すか
(`screen`) は、設定と同じ 1 枚の `settings.json` に書きます。

## 配布構成

```text
dist\app-csharp\
  ReaderDataViewer.vbs
  ReaderDataViewer.cmd
  settings.json                設定・データ定義・画面定義 (この 1 枚)
  data\tableA.csv
  data\tableB.csv
  data\tableC.csv
  data\delete.csv              key2 と b_ref の組による削除例
```

`.vbs` が通常の入口で、コンソールを表示せずに `.cmd` と同じ payload を起動します。`.cmd` は診断時に
コンソールを見たい場合の入口です。どちらも Windows PowerShell と .NET Framework 同梱の `csc` だけを
使います。

統合台帳 xlsx は配布物へ入れません。初回起動では台帳が無いことを確認ダイアログで知らせ、承認後に
3 表から `ReaderDataViewer-Ledger.xlsx` を作ります。出荷例の削除入力は `delete.csv` 1 本を 2 回読み、
`key2` と `b_ref` で選んだ行集合の積集合だけを削除します。

## ソース構成 (`src/csharp/`、コンパイル順は `build/sources.ps1`)

| ファイル | 責務 |
|---|---|
| `Rdv3Core.cs` | CSV / Excel 入力の振分け、列数・キー幅の検査、CSVの行オフセット、時計 |
| `Rdv3Index.cs` | 結合索引と、複数列の完全一致索引／部分一致走査 |
| `Rdv3Ledger.cs` | 台帳行の組立て、マージ／置換、アプリ所有列に定義された変更規則の適用 |
| `Rdv3Xlsx.cs` | 入力表としての xlsx 読取り、台帳 xlsx の読書きと安全な置換 |
| `Rdv3Shared.cs` | 手元の未送信データ、共有書込みのロックファイル、版を知らせる符丁ファイル |
| `Rdv3Jobs.cs` | worker スレッド、ジョブ列、run ID、タイムアウト |
| `Rdv3Json.cs` | 厳格な JSON 読取り (コメント可、未知メンバー・型違い・範囲外はエラー、行番号とテキスト位置を保持) |
| `Rdv3Data.cs` | `data` — 表、列型、順序付きジョブ、行の行き先、列所有、照合方法。ヘッダー・型との突合せ |
| `Rdv3Process.cs` | 表／行集合／台帳の型検査と、結合・抽出・列操作・計算・集計・並べ替え・重複除去・追加・更新・削除・マージ・置換の実行 |
| `Rdv3Config.cs` | `settings.json` 全体の読込みと検証、`paths` / `search` / `watch` だけの書戻し |
| `Rdv3Screen.cs` | `screen` — 画面定義のモデルと読込み、`data` の台帳列との突合せ |
| `Rdv3Values.cs` | 値束縛の評価 (`Rdv3View` / `Rdv3Fields` / `Rdv3Eval`)、書式、判定、作業状態、文言の穴埋め |
| `Rdv3Uia.cs` / `Rdv3Watch.cs` | UI Automation による監視対象の読取り |
| `Rdv3Text.cs` | プログラム自身の文言 (状態語、通知、エラー、固定モーダル) |
| `Rdv3Ui.cs` | JSON 定義から標準 WinForms 部品を並べるメイン画面 `Rdv3Form` |
| `Rdv3Modals.cs` | 標準部品による確認、候補、処理内容、出力、更新通知の各モーダルと通知 |
| `Rdv3Settings.cs` | 設定モーダル、要素ピッカー |
| `Rdv3App.cs` | 入口、状態遷移、検索、作業状態の遷移・保存、台帳更新、計時、ログ |

UI スレッドは重い処理を持ちません。読込、索引、結合、比較、検索、保存は worker スレッドで行い、
結果だけを UI に反映します。run ID が一致しない古い結果は破棄してログに残します。候補一覧モーダルは
worker から `BeginInvoke` で開くので、操作者が選ぶ間も worker は塞がりません。

## 定義が決めること、プログラムが決めること

| `settings.json` | プログラム (C#) |
|---|---|
| `data`: 入力表、順序付きの表操作、キーと条件、3種類の行の行き先、列の持ち主と変更規則、照合列と一致方法 | 入力の検査、操作の型検査と実行、索引／走査、台帳の組立て、xlsx の見出し |
| `screen`: セクションの種類・順序・余白・幅・行高・ラベル | レイアウト計算、レスポンシブな再配置、描画、DPI |
| `screen`: 各値が台帳のどの列か、連結、書式、空のときの表示 | 列の解決、評価 |
| `screen`: 判定の規則 (equals / pattern / empty) と結果の表示名・見た目 | 規則の評価。一致なし = 未定義、列なし = エラー |
| `screen`: 作業状態の名前・見た目・保存値・初期値・遷移・確認文・ボタン文言 | 遷移の実行、手元の控えへの保存、送信、終了保護 |
| `screen`: 候補一覧の列と見た目 | 検索、一覧モーダル、選択 |

計算列と更新値の式は、列・数値・文字、四則演算と3つの文字列関数だけです。任意のコードや一覧外の関数は実行しません。
画面の部品は 8 種類、値の取り方は 3 種類、判定規則は 3 種類だけです。

## 壊れた入力では動かない

`settings.json` は起動時に厳格に読みます。無い、読めない、知らないメンバー (typo)、型や範囲の違う値、
何も指していない名前 (無い表・列・状態・判定) — どれか 1 つでも、起動せずにファイル名・行・理由を
ダイアログとログに出して終了します。組込みの既定はありません (出荷する `settings.json` が唯一の定義)。
定義が使う列は、窓を開く前に CSV / Excel のヘッダー行と突き合わせます。宣言された日付・数値列の
非空値もこの時点で検査します。未宣言列は文字列で、値の形から型を推測しません。

CSV の列数違い、引用符で始まる列、キーの空・幅違い・ASCII 以外、一意であるべきキーの重複は、
ファイル名と行番号を挙げて拒否し、起動時なら起動せず、「台帳更新」で見つかれば理由を出して終了します。
値の制御文字は台帳の区切りや XML を壊さない `?` へ置き換え、読み込みを続けます。文字コードの不一致と
同じく、最初に見つけた行と制御文字コードを更新／削除ダイアログの検証列に出します。

## 台帳

統合台帳は更新ジョブの行元表 1 行を 1 レコードとします。列は `data.ledger.columns.source` と
`data.ledger.columns.application` に分かれます。出荷定義では作業状態がアプリ所有で、残り28列が入力側所有です。
identity は `data.ledger.identity` に明記します。

出荷定義の更新段はマージです。元だけの行を追加し、両方にある行は入力側の内容を更新し、先だけの行を
残します。このため、次の入力に以前の行が無くても同じ xlsx に残ります。入力側の列が変わったときに
アプリ所有列を初期値へ戻すか保つかは、その列の `onSourceChange` が決めます。`targetOnly` を `delete` と明記した設定、または既存列で対象を選ぶ
削除段だけが行を消します。置換も更新段として残っています。

xlsx は一時ファイルへ書き、完成後に置換します。検索しただけでは台帳を変更しません。列名の並びが定義と
合わない台帳、識別列が空または重複した行がある台帳、セルにタブ文字がある台帳は読みません
(ファイル名・列・行番号を挙げます)。読むときは他の端末の置換を妨げない共有モードで開きます。

## 保存中の終了保護

作業状態の変更は、小さい手元の控えへ保存します。共有台帳へ書くのは「送信」を実行したときだけです。
送信と台帳更新は同じロックファイルを取り、ロック内で共有台帳を読み直してから identity で変更を当て、
xlsx を安全に置換します。結果が未確定の間は次の変更と終了を拒否します。各端末は小さい符丁ファイルだけを
定期確認し、版が変わったときだけ xlsx を読み直します。

## UI Automation

監視対象の探索、要素特定、値取得は UI Automation で行います。アプリは対象へ入力せず、値を読むだけです。
複数の監視対象を設定でき、最初に確定した番号が検索を開始します。

設定形式は [settings.md](settings.md)、画面定義と受け入れ条件は [ui-spec.md](ui-spec.md) を参照してください。
