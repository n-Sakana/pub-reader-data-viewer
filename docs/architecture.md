# C# 版アーキテクチャ

Reader Data Viewer の現行製品は C# / WinForms 版です。CSV を読み (出荷定義では 3 本、A-B を key1、B-C を key2 で)
結合し、検索・表示・判定・作業状態の保存を行います。CSV が何か (`data`) と画面に何を出すか
(`screen`) は、設定と同じ 1 枚の `settings.json` に書きます。

## 配布構成

```text
dist\app-csharp\
  ReaderDataViewer.vbs
  ReaderDataViewer.cmd
  settings.json                設定・データ定義・画面定義 (この 1 枚)
  ReaderDataViewer-Ledger.xlsx
  data\tableA.csv
  data\tableB.csv
  data\tableC.csv
```

`.vbs` が通常の入口で、コンソールを表示せずに `.cmd` と同じ payload を起動します。`.cmd` は診断時に
コンソールを見たい場合の入口です。どちらも Windows PowerShell と .NET Framework 同梱の `csc` だけを
使います。

## ソース構成 (`src/csharp/`、コンパイル順は `build/sources.ps1`)

| ファイル | 責務 |
|---|---|
| `Rdv3Core.cs` | CSV の厳格な読込 (列数、引用符、キー幅を行ごとに検査)、行オフセット、時計 |
| `Rdv3Index.cs` | `Dictionary<string, List<int>>` による結合・検索索引 (表のキーは一意、重複は拒否) |
| `Rdv3Ledger.cs` | 定義どおりの結合 (spine + joins + ledger.columns)、内容比較、作業状態の引継ぎ |
| `Rdv3Xlsx.cs` | xlsx の読書きと安全な置換。先頭列が作業状態 (見出し・値は画面定義) |
| `Rdv3Jobs.cs` | worker スレッド、ジョブ列、run ID、タイムアウト |
| `Rdv3Json.cs` | 厳格な JSON 読取り (コメント可、未知メンバー・型違い・範囲外はエラー、行番号とテキスト位置を保持) |
| `Rdv3Data.cs` | `data` — 表、キー、結合、台帳の列。ヘッダー行との突合せ |
| `Rdv3Config.cs` | `settings.json` 全体の読込みと検証、`paths` / `search` / `watch` だけの書戻し |
| `Rdv3Screen.cs` | `screen` — 画面定義のモデルと読込み、`data` の台帳列との突合せ |
| `Rdv3Values.cs` | 値束縛の評価 (`Rdv3View` / `Rdv3Fields` / `Rdv3Eval`)、書式、判定、作業状態、文言の穴埋め |
| `Rdv3Uia.cs` / `Rdv3Watch.cs` | UI Automation による監視対象の読取り |
| `Rdv3Text.cs` | プログラム自身の文言 (状態語、通知、エラー、固定モーダル) |
| `Rdv3Ui.cs` | 描画基盤 (`Rdv3Skin`: トークン、GDI 文字、角丸、タグ、アイコン)、`Rdv3Btn`、メイン画面 `Rdv3Form` |
| `Rdv3Modals.cs` | モーダル基底と暗転、確認モーダル、候補一覧モーダル (+ 表)、トースト |
| `Rdv3Settings.cs` | 設定モーダル、要素ピッカー |
| `Rdv3App.cs` | 入口、状態遷移、検索、作業状態の遷移・保存、台帳更新、計時、ログ |

UI スレッドは重い処理を持ちません。読込、索引、結合、比較、検索、保存は worker スレッドで行い、
結果だけを UI に反映します。run ID が一致しない古い結果は破棄してログに残します。候補一覧モーダルは
worker から `BeginInvoke` で開くので、操作者が選ぶ間も worker は塞がりません。

## 定義が決めること、プログラムが決めること

| `settings.json` | プログラム (C#) |
|---|---|
| `data`: どの CSV か、キー列、どの表が台帳の行か、何で結合するか、台帳の列順 | CSV の読込みと検査、索引、結合、台帳の組立て、xlsx の見出し |
| `screen`: セクションの種類・順序・余白・幅・行高・ラベル | レイアウト計算、レスポンシブな再配置、描画、DPI |
| `screen`: 各値が台帳のどの列か、連結、書式、空のときの表示 | 列の解決、評価 |
| `screen`: 判定の規則 (equals / pattern / empty) と結果の表示名・見た目 | 規則の評価。一致なし = 未定義、列なし = エラー |
| `screen`: 作業状態の名前・見た目・保存値・初期値・遷移・確認文・ボタン文言 | 遷移の実行、確認、即時保存、引継ぎ、終了保護 |
| `screen`: 候補一覧の列と見た目 | 検索、一覧モーダル、選択 |

JSON に式やコードは無く、部品は 7 種類、値の取り方は 3 種類、判定規則は 3 種類だけです。

## 壊れた入力では動かない

`settings.json` は起動時に厳格に読みます。無い、読めない、知らないメンバー (typo)、型や範囲の違う値、
何も指していない名前 (無い表・列・状態・判定) — どれか 1 つでも、起動せずにファイル名・行・理由を
ダイアログとログに出して終了します。組込みの既定はありません (出荷する `settings.json` が唯一の定義)。
定義が使う列は、窓を開く前に CSV のヘッダー行と突き合わせます。

CSV も同じです。列数の違う行、引用符で始まる列、キーの空・幅違い・ASCII 以外、一意であるべきキーの
重複は、ファイル名と行番号を挙げて拒否し、起動時なら起動せず、「台帳更新」で見つかれば理由を出して
終了します。黙ってずらしたり、飛ばしたり、直したりはしません。

## 台帳

統合台帳は spine の表 (出荷定義では表 B の明細) 1 行を 1 レコードとし、`作業状態` (列名は
`screen.workState.store.column`、出荷定義では「処理済み」) と `data.ledger.columns` の内容列 (出荷定義
では 28 列) を持ちます。identity は spine のキー (出荷定義では一意な key2) です。

CSV 更新時の引継ぎ条件は次の 2 つです。

1. 旧台帳に同じ identity がある。
2. 内容列が完全一致する。

一致すれば保存値をそのまま引き継ぎ、新規行・内容が変わった行は初期状態に戻します。xlsx は一時ファイルへ
書き、完成後に置換します。検索しただけでは台帳を変更しません。列名の並びが CSV と合わない台帳は
読まずに「作り直すか」を尋ねます。

## 保存中の終了保護

作業状態の変更は 1 件ずつ即時保存します。その保存が未確定の間は次の変更と終了を拒否し、理由を通知に
出します。保存が成功または失敗として確定すると終了を許可します。保存要求をキューへ溜めたり、終了時に
まとめて保存したりしません。

## UI Automation

監視対象の探索、要素特定、値取得は UI Automation で行います。アプリは対象へ入力せず、値を読むだけです。
複数の監視対象を設定でき、最初に確定した番号が検索を開始します。

設定形式は [settings.md](settings.md)、画面定義と受け入れ条件は [ui-spec.md](ui-spec.md) を参照してください。
