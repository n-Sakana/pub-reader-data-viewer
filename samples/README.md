# 期間混在サンプルを順に試す

架空入力を使い、初回の100件から保護・削除・更新・復元まで確認します。両版で同じ入力を使います。設定は各版に同梱した `settings.json` を使い、版を取り違えないでください。

## 初回の準備

新しい空フォルダにZIPを展開します。最初の `data` は `samples/initial` と同じ4入力です。再試行は新しい展開先で行います。既存の業務台帳や未送信変更を消して初期化しないでください。

`ReaderDataViewer.vbs` を開き、台帳の新規作成を承認します。初回入力は①②③④が各100件。統合100件、決済済80件、未決済20件、③の情報がない行20件です。自動監視元は設定で確認し、この手順を手入力で試す間は監視を無効にします。

1. 「データ削除」を実行します。全行未処理なので0件削除、通常100件・保管0件です。
2. 下表の21件を順に手入力検索し、各案件の「未処理」を押して「処理済」にします。自動読取の場合、この21件は決済済みなので、案件確定後に自動で処理済になります。二重に押さないでください。未決済は自動で処理済になりません。
3. まだ送信せず「データ削除」を実行します。削除0件のままです。未送信21件は削除・更新保護の条件になりません。
4. 「変更をまとめて送信」で21件を保存します。未送信は0件です。
5. 「データ削除」を実行します。最初の20件だけが削除され、通常80件・保管20件。通常行の決済済60件、未決済20件です。21件目のAは処理済のまま残ります。

## 次期間が混ざった入力へ替える

1. `RL10002877BX` を手入力検索して処理済にします。**この1件は送信しません。** 未送信のまま更新する案件Dです。
2. `samples/next-period` の4入力を `data` の同名ファイルへコピーします。**台帳・設定・ログを置き換える操作ではありません。** 各入力は引き続き100件で、過去分に加えて訂正・次期間の新規案件が混ざっています。
3. 「データ更新」を実行し、内容を確認して更新を承認します。通常81件・保管20件になります。未送信Dは保存済み状態が未処理なので、内容の訂正対象です。その変更は新しい内容と競合し、送信できない変更として残ります。

| 案件・オーダーID | 次期間入力 | 期待する台帳 |
|---|---|---|
| A `ORD-KI10002740WM-0020` | 氏名「送信後の訂正名」、金額7200、③備考の訂正 | 全項目を初回のまま保持。氏名「佐藤 一郎」、金額4100、処理済 |
| B `ORD-AA10000000AA-0000` | 氏名「削除後の訂正名」、金額6100、③備考の訂正 | 通常検索に出ず、削除保管は初回の全内容・処理済のまま |
| D `ORD-RL10002877BX-0021` | 氏名「未送信の訂正名」、金額7300 | 今回の内容へ更新。共有の処理状態は未処理。旧内容に対する手元の変更は送信不可 |
| 空欄訂正 `ORD-YO10003014GI-0022` | ②氏名と③備考欄・変更内容が空欄 | 元の氏名「高橋 次郎」等を空欄へ更新。金額4210、未処理 |
| 今回なし `ORD-FR10003151LT-0023` | ①②③から外れている | 初回の全内容を保持。氏名「田中 三郎」、金額4265、未処理 |
| C `ORD-ZZ19999999ZZ-0100` | 次期間の新規行 | 氏名「新規 五郎」、金額5000、未処理で追加 |

検索にはオーダーID内のカード番号を使います。例えばAは `KI10002740WM`、Bは `AA10000000AA`、Cは `ZZ19999999ZZ` です。オーダーID全文は台帳の識別キーです。

未送信Dの競合は、送信時の一覧で内容を確認できます。「保留」なら変更を保持します。このサンプルを終える際に破棄する場合も、検査用のDだけを確認して破棄します。内容訂正後の案件を処理済にしたいなら、旧変更を解決した後で新しい内容を確認して付け直し、送信します。

## ②だけを差し替える

`samples/partial-pay` にある②だけを `data` の同名ファイルへコピーし、「データ更新」を実行します。①③④は次期間入力のままです。

- 通常81件・保管20件を維持します。
- Aの入力金額は9000に変わりますが、台帳は初回4100・処理済のままです。
- Bの入力金額は9001ですが、通常台帳へ復活せず、削除保管の初回3000を保持します。
- 空欄訂正の案件は氏名「部分差替 新名」、金額3333へ変わります。③の備考欄・変更内容は空欄のままです。
- 今回入力にない案件も引き続き保持します。

## 復元して再起動する

1. 「削除済み」を開き、Bの識別キーボタンを押して全内容を確認します。氏名は「佐藤 一郎」、金額3000、処理済です。今回入力の訂正値には変わっていません。
2. Bをチェックして「選択したレコードを復元」を実行します。通常82件・保管19件になります。Bは検索でき、初回の全内容と処理済が戻ります。
3. 残る19件を選択して復元します。通常101件・保管0件です。
4. 終了し、同じ展開先から再起動します。通常101件・保管0件、A/Bの初回の全内容・処理済を確認します。入力が引き続き次期間の値でも上書きされません。未送信Dを保留していれば、その変更は別に残っています。

復元した行が④にある状態で「データ削除」を再実行すると再び削除されます。この確認手順の最後では実行しません。通常の帳票出力には保管中の行を含めません。

設定変更の可否と旧台帳の移行は [PROTECTION-GUIDE.md](../manual/PROTECTION-GUIDE.md) を参照してください。件数と主要キーの機械読取用一覧は `expected.json` です。
