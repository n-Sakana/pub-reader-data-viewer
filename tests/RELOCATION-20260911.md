# 配置・一式移動・確認状態の検証

比較元は固定版公開 `3ca9434`。前回のレビュー修正と `ec6aefc` の比較は [REVIEW-20260911.md](REVIEW-20260911.md) に残す。今回は先生の明示許可により保存列名を「処理状態」から「確認状態」へ変更した。状態値、照合条件、決済判定、削除条件、固定HTML/WPF/WebView2、ライセンスは変更していない。手元Windowsの隔離した架空サンプルで検証した。

## 再現と修正

- `%RDV_PATH_PROBE%` を含むフォルダーで同名の環境変数を別の値にしてVBSを起動すると、WScript.Shell.Runが引用符内のパスを展開し、PowerShellが起動対象を見つけられなかった。直接 `-File` を渡したコンパイルは成功した。VBS側でパーセントを一度だけ復元し、従来の起動方式を維持した。
- セミコロンを含む配置では、同梱WebView2Loader.dllの探索用PATHが途中で分かれ、DLL読込失敗を「WebView2 Runtimeがない」と表示した。同じDLLを実ファイルの絶対パスから読むと、インストール済みのRuntime 152.0.4191.66を取得できた。起動時に同梱DLLを絶対パスで読み、失敗時は具体的な理由も表示する。
- 未送信1件を残して一式を移動すると、旧配布は未送信0件を表示した。未送信保存先を台帳の絶対パスから作っていたため、移動前のデータを参照できなくなっていた。正規の保存方式を、台帳の隣にWindows利用者・端末ごとの参照ファイルを置く形へ変更した。値自体は利用者のLocalAppDataに保持する。一式移動では同じ保存先を参照し、元台帳も残るコピーでは独立した複製を作る。
- CSVと保存済み台帳の内容差分があるときの確認を、「CSVから読み取った内容と、保存済みの統合台帳に違いがあります」とした。「はい」で反映、「いいえ」で台帳を維持し、変更行の確認状態を戻す理由と送信済確認済・削除済の保護を表示する。移動だけでは確認を出さない。

## 今回追加していた互換処理の除去

先生の最新指示で旧列名・旧台帳の互換要件は撤回された。実装済みだった次の5経路を取り除いた。

1. 旧設定の「処理状態」を「確認状態」として扱う正規化。
2. 台帳・アーカイブの旧見出しを受け入れる別名処理。
3. 新旧列名で同じ保存契約識別値になるようにする変換。
4. 旧来の絶対パス由来の未送信保存先を探して取り込む処理。
5. 参照ファイルの保存失敗を通知だけにして、別経路で処理を続行する処理。

新しい設定・新規台帳・更新・送信・削除Excelは「確認状態」で扱う。旧列名の設定は対応しない旨を表示して起動を停止する。参照ファイルや参照先が不正・不在の場合、また参照保存に失敗した場合も停止する。既存の利用者データを削除していない。互換処理が入っていた試作配布とその試験結果は最終配布の根拠から外した。

## 生成配布物のWindows実窓

対象は `build.bat package` で生成した `build/packages/build-20260911-115634-738b217b/ReaderDataViewer-fixed-layout.zip`。互換処理除去後のZIPを2回展開し、表示中の窓をマウスとキーで操作した。UI Automationは窓・部品の位置と表示値の取得に用い、模擬ブリッジや画面外部品の操作を実窓成功に数えていない。

配置名には日本語、空白、`[ ] & ( ) ! % ' # + , ; = $` を含め、`RDV_PATH_PROBE=expanded` も設定した。ケースAは同じ配置で一連の操作を行い、ケースBは展開後・未送信保存後・削除後の3回、一式を別名へ移動した。

両方で次を確認した。

- 新規作成3件、手動A検索は未確認、実メモ帳のA自動検索は確認済、B自動検索は未確認。Bの手動確認と取消も成功。

- 送信後の再起動でA確認済・未送信0。削除後は台帳2件、削除済Aの検索は0件。

- 同名4CSVだけを5月分へ差し替え、内容差分の確認に「はい」と応答して5件へ更新。新規I・既存Bの決済済表示を確認。CSV更新前後の設定ファイルは同一。

削除画面の注意文は「確認状態は共有台帳に保存済みの値で判定します。未送信の変更は送信してから削除してください」。両ケースで `selected=1 result=2`、台帳保存成功、操作ログ保存成功を確認した。パスに関するエラーは出なかった。

実窓操作スクリプトの初回には、入力欄の表示前に操作する待機不足と、更新後に検索表示がクリアされる通常動作を考慮しない検査があった。表示待機と再検索へ修正し、ケースAは同じ隔離データから続行、ケースBは修正済み手順で全操作を完走した。製品側の変更は加えていない。
