# 固定版レビュー修正の検証

対象は固定HTML/WPF/WebView2版。比較元は ec6aefc。main の統合点 45a2e52 は ec6aefc と同じ tree。設定・CSV・業務定義の変更はない。検証には隔離した架空サンプルだけを使用した。

## 修正と再現

- Excel 16.0 の実保存で、元版の関連付けのない contract/protection XML が消え、削除情報を失った Legacy 台帳になることを再現。Workbook の Custom XML relationship と properties を付け、Excel が部品名を変更しても関係から読む。旧 v1/v2 のルート XML も読む。削除全内容は別の archived Excel にあり、主台帳には戻さない。Legacy 台帳の移行で既存 archived を黙って捨てる経路は停止し、元ファイルを保全する。
- 帳票の保留中2条件と即時OKを修正前のブラウザー試験で再現。要求ごとに項目・演算子・値を保持し、返信IDとモーダルの世代を照合する。保留中のOKは確定しない。順序が逆の返信、重複、取消・再表示を検査した。
- ピッカーで設定画面を再構築していたため、未保存の75件・パス・番号形式を失うことを再現。既存の編集欄を保持する。通常保存・設定全体の取消は従来どおり。実窓の反復中に、144 DPIで自窓の除外範囲が物理座標とDIPを混在させ、右側の自WebView2を照会して応答が遅れることも発見。範囲の両端をPointToScreenでそろえた。修正後の配布物は同じ位置で応答を保ち、実メモ帳の選択を4回連続で成功し、75件も保持した。
- 操作ログと控えがともに保存できないときは、台帳保存済みで再送信・再実行不要と通知する。無効検索は生の入力値を記録せず、文字数と拒否理由を残す。
- 配布にない変換スクリプト・docsへのエラー案内を修正。ズームを残したまま設定窓をスクロール可能にした。印刷は画面用の固定高さを解除した。元版の40行の意見欄は1ページのPDFに22行と23行目の一部しか残らず、修正版は2ページで40行すべてと計画・決済・下部項目を保持する。短い4行サンプルは元版でも全項目が紙面内にあった。
- ZIP内の名前を標準の `/` に統一。月次サンプル生成はPATH上のPython（標準ライブラリ）とNodeで実行でき、2回とも既存8CSVとバイト一致した。通常ビルドは既存CSVを使う。

## 回帰の入口

Windows PowerShell 5.1 から、リポジトリ直下で実行する。

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File tests/Test-Review.ps1
# 比較元のソース一式がある場合。成果は毎回別ディレクトリへ作る。
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File tests/Test-SpecParity.ps1 -BaselineRoot C:/path/to/ec6aefc
# 実Excelを2回保存。作成したExcelだけを終了する。
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File tests/Test-ExcelRoundTrip.ps1 -AppRoot C:/path/to/unpacked-package
# 分離アーカイブの再実行入口
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File tests/Test-ArchiveSeparation.ps1
```

Web検査にはPythonのPlaywrightとChromium、サンプル再生成にはPython 3とNodeが必要。通常の `build.bat package` にテストの強制追加はしていない。標準のC#入口は `build.bat test`。

C# 121/121、Web 24/24、パッケージ13/13、公開境界5/5を確認した。ArchiveSeparationは主台帳置換失敗の保全・別Excel・再取込防止・v1移行・繰返し削除を2回実行。比較元と修正版の定義・全行・全状態・決済判定・未確認は削除されないこと・3→2→5・送信済み行の全内容保持・削除再取込防止は同一のJSONスナップショットになった。100件fixtureの双方決済条件・03の左結合・削除の照合条件も通過した。

既存Test-BuildとTest-ReleaseBoundaryに残っていた旧配布の `manual/release.json`、3CSV+1Excel、廃止済み同梱manual、出力前からあるoutputの期待を、比較元ec6aefcの現行配布に合わせた。製品の不具合試験の期待は緩めていない。Test-PaymentBasisの旧100件設定に対するidentity確認はそのfixtureをActualConfigに指定して実行し、現在の5件設定は別途SpecParityで比較した。

## Windows実窓と配布物

`build.bat package` で生成したZIPを展開し、VBSから起動。UI Automationは表示中の部品の位置取得に用い、実際の前面窓をマウス・キーで操作した。画面外部品のInvoke、模擬WebView通信、CDP操作を実窓成功に数えていない。自動読取は実メモ帳、帳票は実CSV、印刷は印刷画面からMicrosoft Print to PDFへ保存したファイルを描画して確認した。

実施：初期3件、手動検索Aは未確認、自動読取Aは確認済・Bは未確認、Bの手動変更と取消、一括送信、再起動後のA確認済/B未確認/未送信0、既定帳票、Aだけ削除して2件、同名4CSV上書き後5件、新規Iと既存Bの決済済。更新前後のsettings SHA-256は `6269f7f47134dd4eeb1fc35c8654ee92cbfa4d0c2dd78bf2aba183d421c2bddf` で一致。

未送信Aを含む実CSVは「確認済＝TRUE」「取引IDにFT260415_を含む」の2条件でAの1件となり、その時点の保存台帳は全件FALSEだった。ピッカーの選択・取消後も75件と各編集が残り、保存後に75件が再表示され、設定取消ではファイルハッシュが変わらなかった。設定150%ズームはスクロールでOK/キャンセルへ到達した。

隔離台帳の操作ログとその台帳専用spoolの保存先だけを一時的に空ディレクトリで塞ぎ、実送信後の通知・台帳TRUE・未送信0を確認。塞いだ2か所だけを元に戻した。無効な架空氏名は `ignored length=14 reason=bad-key` となり、入力本文はログにない。

配布候補 `build-20260911-073238-2aa59d56` で上記一連を実施。後続 `build-20260911-075624-6283d7b3` は印刷時の `.win` の配置だけを追加修正し、印刷・README操作を再確認。その配布コードをExcel 16.0で2回実保存し、全セル・状態・業務定義・削除1件・アーカイブ参照・アーカイブのバイト不変・削除再取込防止・書込可能状態を確認した。

最終候補は `build-20260911-081638-e37dd5c1`。直前の候補から変わったファイルは `src/02_MainWindow.cs` の自窓座標計算と生成時刻の `src/release.json` だけで、ハッシュで照合した。最終ZIPを改めて展開してピッカーの反復、設定ズーム、READMEの保存・再起動・削除・更新を実施した。075624のピッカー再試験で選択が成立しなかった画像は成功証跡に数えない。ビルドの同梱表計算・印刷・帳票コードと設定・CSVは、実保存・実出力を確認したものと同一である。

配布マニフェストのsourceCommitはビルド時のec6aefc、sourceDirtyはtrue。配布ファイルのSHA-256はpackage-manifest.jsonにあり、検証済み候補と最終コミットのソースを照合して公開する。ビルダー自身のwindowsUI欄は自動で実窓試験を行わないので、そのままnot_run_by_packagerとしている。

実画像・操作ログ・Excel/PDF実体はローカルの `work/review-20260911/`。これらを公開Gitへ加えない。レビューZIPには標準テスト・fixture・実行入口・記録・build-summary・package-manifest・配布物を同梱し、review-manifest.jsonで各ファイルを照合する。会社環境や運用に関する検証は対象外。
